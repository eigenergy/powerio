# PowerIO 0.12.5 release notes

This patch fixes the Surge JSON, PyPSA CSV and PowerSystems JSON writers so that each tool solves the case PowerIO wrote, fixes storage sign and unit conventions across PyPSA, Surge and normalized networks, corrects XIIDM and CGMES transformer, shunt and terminal readings, teaches the three-phase pandapower reader transformers, tap changers, shunts and switches, makes PowerWorld `.aux` output load and solve in Simulator 24 and reads newer and older `.pwb` saves, adds an element map to `emit`, publishes the browser bindings to npm, and updates the locked Parquet dependency for a security advisory. Package and PowerIO IR versions are 0.12.5; compatibility remains within the 0.12.x series.

Surge JSON output gives parallel branches distinct circuits (#915). Every branch was written with circuit `"1"`, so two branches between the same buses shared one `(from_bus, to_bus, circuit)` key. A circuit the source states, such as a PSS/E `CKT`, is kept; otherwise each bus pair numbers its branches `"1"`, `"2"` and so on, with a reversed branch counted on the same pair. The Surge reader reads a branch circuit other than `"1"`, so a Surge or PSS/E write keeps it.

Surge JSON output states bus shunts on the bus and branch charging once (#919). The writer put every bus shunt only in `fixed_shunts`, which Surge does not add to its admittance matrix, so a Surge solve of case14 or case118 ran with no shunts. Each bus's in service shunt total is now on the bus record, and a `fixed_shunts` record is kept only for equipment with an identity of its own: a Surge or PSS/E shunt id, switching control, out of service status, a second shunt on one bus, or a shunt on a bus whose shunts cancel. The writer also repeated each end's half of the line charging in `b_shunt_from` and `b_shunt_to`, which Surge adds on top of `b/2`; those fields now carry only charging beyond the even split, zero for a plain pi branch. The reader matches: end charging is `b/2 + b_shunt_*` and `g_pi/2 + g_shunt_*`, and an in service `fixed_shunts` record is no longer counted twice.

PyPSA CSV output describes the source case's power flow (#920). A PV or slack bus's `v_mag_pu_set` is the Vg of its first in service generator, because PyPSA holds those buses at the bus setpoint and has no generator voltage setpoint; case9's slack bus was held at 1.0 instead of 1.04. Generators on one bus with different Vg are reported. A bus with a zero base voltage is written at `v_nom = 1` kV, with its lines and shunts rebased on that value and `EMIT.PYPSA.VALUE_SUBSTITUTED`; `v_nom = 0` made PyPSA read every impedance there as infinite or zero. `transformers.csv` states `model = pi`, the source's branch model, instead of PyPSA's T model default. The writer adds `buses-v_mag_pu.csv` and `buses-v_ang.csv` (radians) with the case's bus voltages, which `pf(use_seed=True)` starts from, and the reader takes bus voltages and angles from them, so a PyPSA CSV round trip keeps them. A generator without a `v_mag_pu_set` column takes its bus's setpoint, as PyPSA does. A `buses.csv` without a `v_nom` column, which PyPSA writes when every bus has its 1 kV default, reads at 1 kV with `READ.PYPSA.VALUE_DEFAULTED`; it was refused, so a case with zero base voltages could not come back through PyPSA's own import and export.

PowerSystems JSON output writes a line angle difference limit at or beyond 90 degrees as ±pi/2, PowerSystems' unconstrained value (#921). An unconstrained MATPOWER limit of -360/360 was written as ±2 pi radians, which PowerSystems.jl reads as degrees and turns into a ±6.3 degree limit. The source limits stay in the retained extension, so a PowerSystems JSON round trip still reads -360/360, and a constrained limit between 90 and 360 degrees is reported with `EMIT.SIENNA.VALUE_SUBSTITUTED`. A zero-tap branch whose end buses differ in base voltage by more than 1% is written as a `TapTransformer` with tap 1 and reported with `EMIT.SIENNA.ELEMENT_RELABELED`; it was written as a `Line`, which PowerSystems.jl refuses to build. Reading the file back restores the zero-tap branch.

`emit` returns an element map that says which written row each bus, branch and generator became (#916). `EmitResult::element_map()` in Rust, `EmitResult.id_map` in Python, `pio_emit_result_element_map` in the C ABI and `powerio convert --id-map PATH` give it as JSON: for each element `uid`, in module order, the target table, the 0-based row index in that table as written, the target's own key for the row where it has one, and for a branch whether the row's first end is the element's `to` bus. The writer records each row as it writes it, so two parallel branches or two generators on one bus no longer have to be told apart by position. The `matpower`, `psse`, `pandapower-json`, `pypsa-csv`, `surge-json`, `egret-json` and `powersystems-json` writers record maps, and `serialize` returns the identity map over the IR network's `buses`, `branches` and `generators`. Other targets, and an emission that returns the retained source bytes, have no map. An element a writer writes no row for maps to `null` with `EMIT.ELEMENT_MAP.UNMAPPED`. `key` is always a string; look egret and pandapower rows up by key. The guide's Element maps section gives each target's tables, indices and keys. No written byte changes.

Each release publishes the browser bindings to npm as `powerio-wasm`, at the same version as the Python wheel and the crates (#917). The package is the converter's `wasm-pack --target web` build with SINCAL support, and `npm install powerio-wasm` replaces building the Rust crate and a wasm32 Clang for SQLite locally.

Storage power has one convention throughout: `Storage.ps` and `qs` are positive when the unit charges and stay in MW and MVAr after normalization. The PyPSA reader negates a `StorageUnit` `p_set` and `q_set`, which are injections, and the writer negates them back (#914). The Surge reader and writer flip the sign of a storage unit's `p`, `q`, `qmin` and `qmax`, which Surge states as generator output (#948). `to_normalized` keeps storage power in MW as PowerModels does, and the stated-state mismatch, the AC OPF preparation and bus merging now convert it, so a network and its normalized copy give the same results; `BalancedNetwork::storage_power_scale` states the factor (#950).

XIIDM and JIIDM: a three winding transformer leg's ratio tap step `rho` divides the winding tap, as it does for a two winding transformer (#912). A `shuntNonLinearModel` section states the accumulated admittance with all previous sections active, as PowSybl reads it (#944). A two winding transformer writes the sum of both terminal charging values into its shunt, and a nonzero to side reports `EMIT.XIIDM.VALUE_COLLAPSED` or `EMIT.JIIDM.VALUE_COLLAPSED` (#946). CGMES: equipment with a terminal at SSH `connected` false reads out of service, also when SV or SSH states `inService` true (#913).

The three-phase pandapower reader maps the `trafo`, `shunt` and `switch` tables (#879, #880, #900, #901): `Dyn` and `YNyn` transformers with a zero sequence that matches pandapower's T model, ratio, symmetrical and characteristic-table tap changers, stepped shunts, and bus-bus, line and transformer switches. A pandapower `runpp_3ph` against OpenDSS oracle covers it.

PowerWorld `.aux` output uses the field names Simulator requires, so Simulator 24 loads every load, shunt, generator, tap, voltage limit and slack bus; it numbers devices per bus, gives a reversed parallel branch its own circuit, and states the system base and zero impedance threshold (#869). `powerio.powerworld.write_pwb` writes a `.pwb` through Simulator's SimAuto server on Windows (#870). The `.pwb` reader reads Simulator 24's default save layout and places a generator that regulates a remote bus on its terminal bus in older layouts (#872, #875).

Sienna emission and pandapower JSON emission report rating-set losses and unrated transformer substitutions in one counted diagnostic each (#908, #923). The C ABI refuses a buffer length beyond the largest Rust slice with `BIND.CAPI.INVALID_ARGUMENT` (#903). Python gains `AcOtsInstance.branch_order`, `initial_closed` and `AcOtsSolution.ac_solution` (#906). The SINCAL reader's `rusqlite` is updated to 0.43.0 (#893).

The locked Arrow and Parquet crates are updated to 60.2.0, which resolves RUSTSEC-2026-0595 in the reading of encrypted Parquet Bloom filter metadata (#909, thanks to BurhanAbdullah). The `gridfm` feature, which reads and writes GridFM Parquet directories, builds against it; the update changes only `Cargo.lock`.

The C ABI release constants and the PowerIO IR schema identify 0.12.5. The schema's content is the 0.12.4 schema with the new identifier. The published 0.12.3 schema, which the 0.12.4 bump moved to the 0.12.4 path, is restored byte for byte at `docs/schema/pio-ir/0.12.3/schema.json`, so the series compatibility test checks it again. The C ABI gains `pio_emit_result_element_map`.

## Upgrade notes

PowerIO 0.12.4 and earlier misread Surge JSON written by 0.12.5. They read a branch with no line charging, because 0.12.5 leaves the even split of the charging out of `b_shunt_from` and `b_shunt_to`, and they count twice every shunt written both in its bus's shunt total and as a `fixed_shunts` record. Read 0.12.5 Surge files with 0.12.5 or later. PowerIO 0.12.5 reads Surge files written by 0.12.4 and earlier with their old meaning and reports `READ.SURGE.LEGACY_LAYOUT`.

A PyPSA CSV folder with one snapshot whose only series files are `buses-v_mag_pu.csv` and `buses-v_ang.csv` now parses as a `BalancedNetwork` carrying that voltage state, where it parsed as a one point operating point series. A `buses.csv` without a `v_nom` column reads at 1 kV where it was refused.

Files written by PowerIO 0.12.4 and earlier read differently where they followed the old conventions: PyPSA `StorageUnit` and Surge storage power from those writers now read with the opposite sign, three winding XIIDM and JIIDM transformer leg taps away from 1 read inverted, and nonlinear XIIDM and JIIDM shunts read as the section they state rather than a sum. The new readings are PyPSA's, Surge's and PowSybl's. Every MATPOWER transformer with nonzero `BR_B` written to XIIDM or JIIDM now reports `VALUE_COLLAPSED`, because the format has one shunt per transformer.

A pandapower document with three-phase tables (`asymmetric_load`, `asymmetric_sgen` or a non-empty `res_bus_3ph`) and `Dyn` or `YNyn` `trafo` rows or stepped `shunt` rows now parses to `MulticonductorNetwork`; 0.12.4 read it as a `BalancedNetwork`. Plain balanced pandapower files are unaffected.

PowerWorld `.aux` reading takes the base MVA from a `Sim_Solution_Options` `SBase` and refuses a non-positive or non-numeric one; a bus name that is blank or equal to the bus number reads as no name in `.aux` and `.pwb`. The `.pwb` reader places a remote regulating generator on its terminal bus in Simulator 17 through 22 layouts, where it used the regulated bus.

The first npm publish of `powerio-wasm` needs the maintainer bootstrap. npm accepts a trusted publisher only for a package that exists, so after the GitHub release is published and the npm workflow's build job passes, the maintainer runs `scripts/npm-bootstrap.sh v0.12.5` once with a local `npm login`, then configures the trusted publisher it prints. Later releases publish through the workflow.
