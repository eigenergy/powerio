# PowerIO 0.12.0 release notes

PowerIO 0.12.0 starts the 0.12.x release series. From 0.12 on, the release
series says what is compatible with what: within 0.12.x, the public Rust,
Python, and Julia APIs only gain items, the C ABI only gains symbols, and newer
readers keep reading older IR documents. Older readers accept compatible
documents for types they support and refuse unknown structural types. A break
to an existing type waits for the next series.

Before 1.0, settle the exposed `sprs::CsMat` and `num_complex::Complex64`
compatibility contract, the conventions and reference/slack questions, and the
remaining public milestone scope. Pre-1.0 dependency versions do not inherently
prevent a stable PowerIO API; choosing to expose their types is a compatibility
commitment. See [the 1.0 readiness checklist](../src/known-limits.md#path-to-10).
This release already replaces `IndexedNetwork::to_petgraph` with the
PowerIO-owned `branch_edges()` interface.

This release removes the version numbers 0.11 carried beside the release,
retires the compatibility shims 0.11 kept, fixes the placement of a three
winding transformer's magnetizing admittance and two XIIDM sign conventions,
adds input collections for ZIP archives and folders of related files, and
raises cross format fidelity. [From 0.11 to 0.12](../src/migration-0.12.md)
lists everything that needs action. The
[curated changelog](../../CHANGELOG.md#0120) gives each change in full.

CGMES parsing now shares repeated class and property names through a bounded
per-document cache. Uncommon and long extension names remain accepted. This
reduces temporary allocations without adding a public type or changing the
electrical model; regression tests cover namespace aliases and both cache bounds.
The parser also reuses the XML property buffers, retains the established
duplicate-property order and conflict errors, and releases spare temporary
capacity before building the typed network. These changes preserve source
replay, diagnostics and canonical output.

Python balanced network handles defer their derived analysis index until the
first topology or matrix query. Reading counts or metadata avoids this work;
the first analysis query still constructs the same index, and later queries
reuse it. Updating a module or constructing a derived network creates a handle
for that network, so an old index cannot describe an edited value.

## What changes

### Reviewed temporal and projection fixes

Egret shunts retain their service flags in scalar and time-series output.
A foreign extra cannot populate an omitted native PowerModels field with the
wrong units; collisions are reported. Partial or foreign-shaped Egret branch
results and DC cost extensions remain extras rather than refusing an otherwise
readable case. Applying operating-point columns clears inherited branch results,
so new voltages or dispatch cannot be exported beside a stale solved flow.

Time-series emission applies the scalar loss checks to every point, reports
identical findings once, and builds varying columns incrementally instead of
holding a complete JSON document for every snapshot. Unsupported topology or
non-electrical variation is still refused. In particular, time-varying system
attributes such as `reserve_requirement`, and unsupported element attributes
even on a one-point axis, now produce explicit errors. Earlier readers could
ignore or flatten these inputs; this release intentionally refuses that silent
projection. The supported electrical profile does not implement unit commitment.

Absent CIM distribution frequency remains 60 Hz for all namespace versions;
namespace version does not identify the grid region. Explicit `BaseFrequency`
still wins. XfmrCode winding-count changes reset the active selector consistently
with Transformer. Nested non-finite extension numbers remain visible as a
`NOT_A_NUMBER` finding, and omitted Egret component identities are diagnosed even
when detailed connectivity is retained. Shared JSON extension helpers keep
identity and extra-field precedence consistent between Egret and PowerModels.

### CGMES limits and tap-changer identity

Typed loading limits and branch ratings consistently prefer active values over
equipment defaults. Transformer current limits use the voltage of the terminal
carrying each limit, including the low-voltage winding. A differing equipment
default that canonical output cannot retain is diagnosed. Ratio and phase
tap-changer identifiers and names survive IR and canonical output, including
modules stored by older readers. Synthetic regressions cover both CGMES
versions, temporary limits, terminal ordering and legacy metadata.

Two-winding transformers follow CGMES's common parameter base and one primary
shunt L model. The supported circuit keeps all four terminal admittances when
rated winding voltages differ from nominal bus voltages, including a nonunit
secondary ratio tap. The equivalent branch multiplies series impedance by the
secondary ratio squared and divides its shunt by that factor; canonical output
applies the inverse. Circuit regressions cover both winding ratios and phase
shifts. Nonconforming low-voltage or split-record parameter conventions produce
an explicit approximation diagnostic describing the assumed reference base.
Invalid active ratio magnitudes and arithmetic overflow are refused. See the
[ENTSO-E implementation guide, section 14.19](https://eepublicdownloads.entsoe.eu/clean-documents/CIM_documents/Grid_Model_CIM/CGM%20BUILDING%20PROCESS%20IMPLEMENTATION%20GUIDE_v2.0.pdf).

The calculation projection still uses only the angle of a nonlinear or
tabular phase tap. An active nonunit magnitude now produces
`READ.CGMES.VALUE_APPROXIMATED`. Active tap-step r/x/g/b percentage deviations
that the calculation projection does not apply are also diagnosed, including
when the ratio magnitude is one. The full steps stay in detailed connectivity;
unused steps do not create these calculation warnings. Canonical output places
two-winding series and shunt data on end 1. Combining a nonzero secondary shunt
into that primary L shunt remains an explicit projection loss. A sole primary
shunt emits without a false collapse warning; unequal line charging retains its
loss diagnostic.

### Sienna and Python interchange

Balanced modules read and write SiennaSchemas 0.1.0, 0.2.0, 0.3.0, and 0.4.0.
The native `powersystems-json` adapter reads PowerSystems data formats 4 and 5
and writes format 5. Pinned schemas and external consumers verify the adapters.
Python adds optional Sienna HDF5 bundles, PyPSA NetCDF/HDF5 transports (#107),
and TransitionZero source/sink plugins. Serialized modules retain companion
arrays and pipeline extensions with their declared interpretation. See
[Sienna exchange](../src/sienna.md) for version selection and fidelity limits.

Repeated retained edits preserve missing generator costs, native component UUIDs,
secondary-shunt identities, and unknown extension keys on surviving records.
A stale transformer association leaves the native shunt at its stated bus and
service state with a diagnostic. Removed records lose their obsolete extension
entries; typed edits take precedence over old semantic markers.

### One version for the release, the C ABI, and PowerIO IR

0.11 stated three numbers: the release, PowerIO IR version 2, and C ABI 7.
The two integers only ever changed when a new release series began, so 0.12
replaces both with the release (#701).

- A PowerIO IR document's header states the release whose schema it
  follows, `"version": "0.12.0"`, described by
  `docs/schema/pio-ir/0.12.0/schema.json`. A 0.12.x reader accepts any
  0.12.z document for a supported structural type and every 0.11 document
  (`"version": 2`) with the meaning it had. Every release from 0.12 on publishes its own schema file; the 0.11
  files under `pio-ir/2/` keep their bytes.
- The C header states the release it was generated from, as
  `PIO_VERSION_MAJOR`, `_MINOR`, and `_PATCH`, and `pio_version_numbers()`
  reports the library's. A program compiled against release 0.12.Z works
  with any 0.12.x library at 0.12.Z or newer. `PIO_ABI_VERSION` and
  `pio_abi_version()` are gone. CI compares `powerio.h` with the latest
  release header in the same series.
- PowerIO.jl checks the library's release series instead of the ABI number,
  and refuses a library older than 0.12 without calling its `pio_version`,
  whose return type differs before 0.11.
- A prerelease build (`1.0.0-rc.1`) states its core release, `1.0.0`, in the
  numbers and the IR header, and its whole version in `pio_version()`,
  `powerio::VERSION`, and `producer.version`.

### Three winding transformer magnetizing admittance

PSS/E connects `MAG1 + jMAG2` from winding 1's bus to ground, outside that
winding's ratio; IIDM and CGMES state each leg's admittance at the star
point. 0.11 placed every three winding magnetizing admittance at the star
point, so a PSS/E unit with an off-nominal winding 1 ratio was off by about
`|Ym|` in `Y_bus` (#741). `Transformer3W::magnetizing_connection` now says
which circuit a record states. The PSS/E readers state
`Winding1Terminal`, and the star lowering puts that admittance on winding
1's branch as from side charging `Ym * tap1²`, which bus 1 sees as `Ym`.
Writers whose format has only the other placement keep the value and report
the move with `VALUE_SUBSTITUTED`. PowerIO IR states the field only when it
is not the star point, so 0.11 documents read as they did.

### XIIDM sign conventions

An IIDM battery states `targetP`, `targetQ`, and its reactive limits as
generation; PowerIO storage states power withdrawn, positive when charging.
A converter station's terminal `q` flows from the bus into the station,
while `Hvdc::qf` and `qt` are injected into the bus. The XIIDM and JIIDM
readers and writers now convert both (#700).

### Input collections

`Collection` acquires a ZIP archive or a folder once, inspects it without
parsing electrical values, and parses independent selections: an OpenDSS
master over shared companions, a PyPSA or GridFM dataset root, or a group of
CIM or CGMES documents (#774). ZIP reads are bounded by explicit size,
expansion, count, and ratio limits and verify every member. The CLI
(`powerio collection inspect` and `parse`), Python (`powerio.Collection`), C
(`pio_collection_*`), Julia (`InputCollection`), and the browser converter
use the same selections. The new `powerio-archive` crate holds the bounded
ZIP transport.

### PowerModels and egret JSON carry more

PowerModels and egret keep keys they do not know, so their writers now state,
under PowerIO names those tools leave alone, what their standard fields cannot
hold: area records, case metadata, source identities, rating sets beyond the
three ratings, the detailed connectivity hierarchy, locations and routes,
controls, generator regulation, and HVDC converter detail. Their readers
restore all of it. [Format fidelity](../src/format-fidelity.md) lists the
keys. With the other writer fixes in this release, among them the MATPOWER
branch flow columns, the conversion matrix has 27 more lossless cells than
0.11.9 and no comparable cell is worse.

### Egret zero thermal limits

0.11.12 and 0.11.11 still read a native Egret numeric `0` in `rating_long_term`,
`rating_short_term`, or `rating_emergency` as unlimited, which relaxes the
zero thermal limit Egret enforces. 0.12 reads it as that zero limit, scalar or
at any time point; `null` and an absent field still read as unlimited (#828).
Branch and winding ratings across the Rust, Python, C, and Julia APIs use zero
for a zero bound and positive infinity for no bound, and formats such as
MATPOWER that write zero for no bound translate it at their reader and writer
(#841). Python table rows state every nonfinite value as a float; the `hvdc`,
`storage`, `static_var_compensators`, `areas`, and distribution rows carried
the strings `"Infinity"` and `"-Infinity"` in 0.11. See
[Numeric thermal ratings](../src/migration-0.12.md#numeric-thermal-ratings)
for what changes, including Egret files that 0.11.10 or earlier wrote.

### BMOPF: one BMOPF

There is one BMOPF. PowerIO reads and writes the schema proposed in
[dsopt-schema#2](https://github.com/distribution-system-opt/dsopt-schema/pull/2),
vendored from the Task Force repository at commit `6796394`. That proposal is
the Task Force's schema plus the classes the Task Force draft carried, with
the review answers and fixes applied. The pin moves to the release tag the
schema's `$id` names once the Task Force ratifies the proposal. No PowerIO
format token, option, or type names a BMOPF version.

- Output states `meta.schema_version`, which the schema requires as the
  document's one version identifier, and no `meta.$schema`; the schema's
  `$id` is in `meta.provenance`. It writes the bus bounds as `vpg_min`/`vpg_max`
  and the neutral to ground cap as `vng_max` (earlier `vn_max`),
  geometry in the typed `bus.*.geo`, `line.*.geo` and `meta.crs` slots, `ibr`
  and `control_profile` as top-level tables, and costs as `energy_cost_rate`.
  Component locations travel as the `geo` Point of the source, load,
  generator, IBR, shunt, capacitor, switch or transformer they attach to.
  `extras.powerio_geo` remains only for a coordinate space the schema cannot
  name.
- A document from an older BMOPF draft (including the `bmopf-report` drafts
  and the early draft PowerIO 0.11 wrote) still reads. It is read as BMOPF
  and reported once with `READ.BMOPF.SCHEMA_LEGACY`. Writing it produces a
  document in the current schema; only a source that states the current
  schema and no `meta.$schema` is echoed byte for byte.
- The schema's identity and consistency changes: any patch release of the
  schema's line reads as current; an absent `meta.crs` means
  `OGC:CRS84` (WGS84, longitude then latitude), which the writer leaves
  implicit; enums are UPPER_SNAKE, `DSTATCOM` is `STATCOM`, the per-unit limit
  token is `PU`, and the regulators' ratio is `voltage_ratio`, with the earlier
  spellings read under the one legacy warning; line `s_max` has one entry per
  conductor; and the writer drops, with a finding, any value the schema now
  rejects (non-positive ratings, nominal voltages, taps and ratios, control
  laws of the wrong shape, bus bounds the bus cannot carry) instead of
  writing it. The reader checks the schema's semantic rules.
- `bmopf-json` is the one BMOPF token. A `bmopf-json@<version>` token, as
  0.11 accepted, is refused with a pointer to `bmopf-json`.
- The Rust crate and the Python package ship the one schema, at
  `schemas/bmopf/bmopf.schema.json`.
- The C ABI's `pio_schema_report` and Python's `powerio.versions()` state the
  schema's `$id` as `bmopf_schema`.
- The pin includes the review fixes to dsopt-schema#2, and multiconductor IVR
  preparation follows them. The inverter power factor sign is the OpenDSS
  PVSystem and Storage convention, `pf > 0` putting Q on the same side as P;
  preparation used the opposite sign. A type-A regulator's `tap_ratio` is the
  regulated over source voltage ratio, as for type B. An inverter's
  `energy_cost_rate` now prices its injection; preparation refused it before.
  `voltage_source.cost` and `ibr.cost` are gone from the schema and read as
  `energy_cost_rate`.

## Pandapower voltage results

Pandapower JSON now reads and writes bus voltage magnitude and angle through
the native `res_bus.vm_pu` and `res_bus.va_degree` columns, including after a
PowerIO IR round trip. Result rows follow bus indices and remain separate from
generator and slack voltage targets. Writing stored states does not claim a
converged solution or invent aggregate bus powers. Unavailable voltage results,
unmatched rows, and result columns without a typed field are diagnosed.
The writer uses pandapower 3.2.1's data format 3.1.0 with separate active and
reactive ZIP-load columns. It omits the older aggregate columns, which cause
duplicate-column errors when mixed with the new fields during native import.
The reader continues to accept both column layouts.

## Egret temporal fidelity and conversion evidence

Egret now writes native signed AC branch results and electrical time-series
values after source retention is removed, including IR round trips. Labels and
optional interval durations are retained; unsupported variation is refused.
The Python native Egret oracle checks snapshot extraction, and C/Julia expose
typed time metadata. Unit-commitment semantics remain outside the profile.

The PR workflow exports exact-commit JSON evidence from the same graded cells
as its table and a deterministic ranked backlog. The website can consume those
artifacts and the main Docs deployment's copies. Review compares fixture
coverage, findings and grades; no automatic process may suppress losses or
accept a baseline to make the matrix greener.

The overview now combines Exact and Lossless as **Preserved**. It explains
representation changes/defaults, adjustments or incomplete checks, and omitted
data in plain language. The raw grades, byte-replay evidence and acceptance
rules remain unchanged. A cell reports its most serious finding, not a
percentage of the file preserved; see [Reading the results](../src/conversion-evidence.md#reading-the-results).
