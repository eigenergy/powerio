# PowerIO 1.0.0 release notes (draft)

PowerIO 1.0 corrects the public OPF contracts introduced in the 0.10 beta.
The 1.0 boundary includes changes to stored solution fields and Rust APIs.
The stored document schema remains `powerio.module/1`.

## OPF input

Balanced DC and AC preparation now compiles the objective and active
constraint selections declared by the instance. The supported objectives are
an empty feasibility objective and the network generator cost. Unsupported
terms, unknown selected identities, and duplicate stable identities return
typed errors.

Network generator costs retain constant, linear, and quadratic polynomial
terms and convex piecewise linear breakpoints. PowerIO does not fit one form to
another. Malformed or nonconvex piecewise rows return typed errors. The nodal
quadratic projection and the legacy DC OPF matrix bundle reject piecewise costs
because those outputs cannot encode the curve.

Preparations include stable bus, generator, and branch identities beside every
dense array. Analysis row numbers and optional source row numbers are separate.
A synthetic branch produced by three winding transformer lowering has an
identity derived from the transformer and winding number and has no source
branch row. Constraint masks follow the same dense order.

AC and DC options both support synthesized thermal limits. Each preparation
records whether synthesis was selected.

## OPF results

Economic outputs describe derivatives of the declared objective instead of
assuming a currency. DC solutions can carry active demand marginals. AC
solutions can carry active and reactive demand marginals. The units are
objective units per MW or MVAr.

Branch thermal results retain the two nonnegative constraint multipliers. DC
uses the positive and negative flow bounds; AC uses the two terminal apparent
power bounds. For a shared rating, the local optimal value derivative is the
negative sum of the two values.

## Stored 0.10 documents

The `differentiability_regularization` objective term is retired because it
did not define a quantity or unit. A 0.10 module containing the token still
reads. PowerIO removes the term and records
`READ.MODULE.OBJECTIVE_TERM_RETIRED`.

The new economic result fields are
`bus_active_power_marginal`, `bus_reactive_power_marginal`,
`branch_from_limit_multiplier`, and `branch_to_limit_multiplier`.
The 0.10 bus price names read as aliases for the demand marginals. The signed
0.10 DC `branch_flow_dual` splits into directional multipliers by sign and
adds `READ.MODULE.BRANCH_DUAL_SPLIT`; the warning states the zero-rating case
where the original two values are not uniquely recoverable.

See [Migrating from 0.10](../src/migration-v1.md) for the Rust API changes
and sign conventions.
