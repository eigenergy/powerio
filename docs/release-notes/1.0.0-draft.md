# PowerIO 1.0.0 release notes (draft)

PowerIO 1.0 corrects the public OPF contracts introduced in the 0.10 beta and
sets the final source vocabulary. The 1.0 boundary includes changes to stored
solution fields and Rust APIs. The stored document schema remains
`powerio.module/1`, and C ABI 6 remains compatible.

## OPF input

Balanced DC and AC preparation now compiles the objective and active
constraint selections declared by the instance. The supported objectives are
an empty feasibility objective and the network generator cost. Unsupported
terms, unknown selected identities, and duplicate stable identities return
typed errors.

Network generator costs retain constant, linear, and quadratic polynomial
terms and convex piecewise linear breakpoints. PowerIO does not fit one form to
another. Malformed or nonconvex piecewise rows return typed errors. The nodal
quadratic projection and the legacy DC OPF matrix bundle reject piecewise costs
because those outputs cannot encode the curve.

Preparations include stable bus, generator, and branch identities beside every
dense array. Analysis row numbers and optional source row numbers are separate.
A synthetic branch produced by three winding transformer lowering has an
identity derived from the transformer and winding number and has no source
branch row. Constraint masks follow the same dense order.

AC and DC options both support synthesized thermal limits. Each preparation
records whether synthesis was selected.

## Cross language API vocabulary

Rust, Python, Julia, and C now document one ordinary path:

```text
parse_file or parse_text -> PioModule { value, diagnostics } -> to_* or calc_* -> emit
```

`to_*` transforms an in-memory value. `calc_*` computes a matrix or vector.
`emit` produces an external representation. The direct PowerModels incidence
operation is `calc_incidence_matrix`; it returns the branch by bus matrix.
Internal solver preparation retains its separately documented bus by branch
factor. Rust, Python, and Julia expose DC matrices and vectors through the
direct named `calc_*` operations. Rust `DcNetworkData` and `dc_network_data`,
Python `dc_data`, and Julia `DcData` are removed without a renamed container
replacement. The existing C ABI 6 `PioDcData` handle remains callable. OPF
preparation projections use
`calc_fixed_nodal_withdrawal`, `calc_branch_flow_offset`, and
`calc_nodal_generator_data`; `emit_dcopf_bundle` produces the legacy matrix
bundle.

Python exposes `PioModule.value` and `PioModule.diagnostics` as properties.
Julia exposes `parse_file` for paths and `parse_text` for in-memory text, with
`value` and `diagnostics` on the module. Rust uses ordinary `PioValue` enum matching through
`module.value()`. C gains additive `pio_module_emit_*`, transformation, state
export, checked branch flow, and graph projection names, including
`pio_balanced_network_to_normalized` and the balanced and multiconductor
`*_to_geo_layer_json`, `*_apply_geo_layer`, and `*_to_module` operations.
The existing C `PioDcData` handle gains `pio_dc_data_calc_branch_flow`.
Collection modules gain `pio_module_list_states_json`, with the released
`pio_module_state_inventory_json` spelling retained.
Module inspection preserves `operations` and adds classified preferred and
compatibility operation arrays.

`resolve_format` is the shared format metadata query. It resolves aliases to
the canonical token and reports the conventional filename suffix, directory
destination shape, and fresh universal emission capability without exposing
Rust component enums. C adds the ABI 6 symbol `pio_resolve_format_json`;
Python and Julia return their native `FormatInfo` records. The capability is
format level: it is not a promise for every module value kind or a build
feature probe.

Rust applications that already own PowerWorld display bytes use
`parse_display(bytes, "pwd")`. `to_geo_layer_from_aux_text` turns an AUX
`Substation` table into an owned geographic layer without leaking the borrowed
component parser type; `to_geo_layer_from_aux_substations(&AuxFile)` remains in
`powerio-tx` but leaves the facade root. Facade `parse_display_file` now returns
`powerio::Error` rather than the component error. Python keeps the single path
based display operation; its private native `parse_display_bytes` entry point
is removed.

The 0.10 high level compatibility spellings are removed at the 1.0 boundary.
The C ABI version remains 6 and every released C symbol remains callable. The
[1.0 API surface](../src/final-v1-api-cleanup.md) inventories the source
replacements and retained ABI symbols.

## OPF results

Economic outputs describe derivatives of the declared objective instead of
assuming a currency. DC solutions can carry active demand marginals. AC
solutions can carry active and reactive demand marginals. The units are
objective units per MW or MVAr.

Branch thermal results retain the two nonnegative constraint multipliers. DC
uses the positive and negative flow bounds; AC uses the two terminal apparent
power bounds. For a shared rating, the local optimal value derivative is the
negative sum of the two values.

## Stored 0.10 documents

The `differentiability_regularization` objective term is retired because it
did not define a quantity or unit. A 0.10 module containing the token still
reads. PowerIO removes the term and records
`READ.MODULE.OBJECTIVE_TERM_RETIRED`.

The new economic result fields are
`bus_active_power_marginal`, `bus_reactive_power_marginal`,
`branch_from_limit_multiplier`, and `branch_to_limit_multiplier`.
The 0.10 bus price names read as aliases for the demand marginals. The signed
0.10 DC `branch_flow_dual` splits into directional multipliers by sign and
adds `READ.MODULE.BRANCH_DUAL_SPLIT`; the warning states the zero-rating case
where the original two values are not uniquely recoverable.

See [Migrating from 0.10](../src/migration-v1.md) for the source API changes
and sign conventions.
