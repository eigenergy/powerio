# PowerIO 0.11.0 release notes

PowerIO 0.10.0 was the public beta for the candidate 1.0 API. PowerIO 0.11
ships the resulting architecture without prematurely declaring its Rust API
stable. Rust, Python, Julia, and C now share one set of operations and one
power system data vocabulary.

The release remains pre-1.0 because public Rust signatures expose
`sprs::CsMat` and `petgraph::UnGraph`, whose crates are themselves pre-1.0.
The 0.11.x line is reserved for compatible bug fixes, performance
improvements, and additive work; an unavoidable breaking public API change
moves to 0.12. A later 1.0 follows a downstream stabilization cycle and an
explicit decision about those dependency boundaries.

## One module model

Parsing returns `PioModule<T>`. A module contains one typed value and its
diagnostics, producer, sources, source mappings, history, and extensions. The
registered values include balanced and multiconductor networks, operating
points, time series, scenario sets, power flow and optimal power flow
instances and solutions, and SCUC instances and solutions.

Rust matches the enum `module.value()` returns. Python uses `module.value` and
`isinstance`. Julia dispatches on `PioModule{T}`. C uses structural type names,
predicates, and owner rooted typed handles. `PioValueKind`, `.kind`, and typed
narrowing wrappers are removed.

`TimeSeries<T>` and `ScenarioSet<T>` support ordinary collection operations.
The selection and export API from 0.10 is removed.

## Parse, emit, serialize, deserialize

Every source enters through `parse`. Rust takes a file or directory name,
content in memory, or a built `Source`; C builds a `PioSource`; Python accepts
a path, file object, or bytes-like object; Julia dispatches on a path string,
`IO`, or `AbstractVector{UInt8}`.

`emit` produces grid exchange formats and returns an `EmitResult`: the
artifacts it produced (one per file, each with its name and either its bytes
or its path), the output layout, the fidelity (an exact same format echo of
retained source bytes, or canonical fresh output), and the emission
diagnostics. The same operation handles memory, one file, and directory
output. `serialize` and `deserialize` handle PowerIO IR.
PowerIO IR is absent from grid exchange format discovery.

PowerIO IR is also the only PowerIO-owned JSON document. The former bare
`BalancedNetwork` JSON methods and `model-json` classifier family are removed;
a network is wrapped in `PioModule` and passed to `serialize`.

Emitting a calculation instance writes its electrical network and diagnoses
calculation fields the target cannot carry. Emitting an AC power flow or OPF
solution also writes supported bus voltages, generator dispatch, and branch
terminal flows. Objectives, multipliers, termination data, residuals, and
other unsupported results are diagnosed. An SOCWR result never masquerades
as an AC solution: emission writes only its instance network and diagnoses
the omitted relaxation values and objective lower bound.

The duplicate beta parse and write names are removed. See
[From 0.10 to 0.11](../src/migration-0.11.md) for the complete inventory.

## Typed updates

`OperatingPointUpdate`, `NetworkUpdate`, and `CalculationUpdate` identify
components by stable `ComponentId` and carry absolute values with explicit
units. `apply_updates` validates the whole batch and applies it atomically.
`UpdateReport` lists every changed component and field and reports whether
energized connectivity changed.

The first update set covers load active and reactive power, generator
setpoints and service status, branch thermal ratings and service status,
transformer tap and phase shift, and switch position. A bus demand command
must name a load or an explicit allocation rule.

## DC calculations

The public DC data bundles and the phrase “DC branch coefficients” are
removed. Public matrices and vectors use their PowerModels and MATPOWER names:

```text
calc_incidence_matrix
calc_branch_susceptances
calc_bus_susceptance_matrix
calc_branch_flow_matrix
calc_branch_phase_shift_injection
calc_bus_phase_shift_injection
calc_branch_flow_dc
calc_bus_injection_dc
```

The incidence matrix is branches by buses with `+1` at the from bus and `-1`
at the to bus. Phase shift injections remain separate. The matrix guide states
the complete signs and equations.

## Calculation results

`SocwrOpfSolution` records the W-space values, generation, terminal powers,
duals, termination, and objective lower bound from a PowerModels SOCWR
relaxation. PowerIO does not label that result `AcOpfSolution` without checked
voltage recovery and AC residual validation.

Economic outputs describe derivatives of the declared objective. Bus active
and reactive demand marginals and the two nonnegative branch thermal limit
multipliers replace the ambiguous beta price and signed branch dual fields.

## GridFM fidelity

GridFM Parquet reads preserve the stated branch terminal flows and fixed
quadratic generator costs. Dense bus indices, nodal load and shunt totals, and
unit-tap line classification are native GridFM representation choices and no
longer produce reader warnings. GridFM output reports the projections it
actually performs from richer source networks; an unchanged GridFM dataset
writes without findings. PowerIO IR records which component identities
PowerIO generated, so writers can distinguish stable internal references from
source metadata. Batch output checks that scenario ids are unique and that the
system base and bus, branch, and generator row identities align.

## PowerIO IR

The serializer and deserializer use `"schema": "pio-ir"` and integer
`"version": 2`. The integer is the PowerIO IR generation and changes only when
the serialized representation changes. The producer record separately names
the PowerIO release, here `0.11.0`; C ABI 7 is independent. Runtime retained
source bytes are not serialized. An unsupported identity or generation is
refused with what the reader found.

`docs/schema/README.md` records one PowerIO IR history. It archives the `0.1`,
`0.2`, and `0.9` schemas produced by the retired `powerio-pkg` crate and the
v0.10.0 `powerio.module` schema as documentation only, all under the single
`pio-ir` archive. The retired payload
schemas are not part of the current representation.

## C ABI 7 and Julia

PowerIO 0.11 ships C ABI 7. It uses opaque reference counted handles, explicit
buffer lengths, one structured error channel, structural type names, and typed
borrowed access without encoding a module value. ABI 4, 5, and 6 symbols are
not present.

PowerIO.jl uses ABI 7 and exposes Julia structs, multiple dispatch, natural
indexing, and mutating operations ending in `!`. It is the supported Julia
binding; Julia consumers do not call the C ABI directly.

## Interoperability

The 0.11 format layer adds XIIDM, JIIDM, CGMES, and PSS/E RAWX support.
PSS/E RAW revisions 32 through 35 are accepted; revision 32 is read only and
fresh output uses revisions 33 through 35. XIIDM and JIIDM are the XML and JSON
encodings of the IIDM model. Versions 1.0 through 1.17 are accepted and fresh
output uses 1.17. CGMES 2.4.15 and 3.0 are accepted; fresh output is a
deterministic 3.0 EQ, TP, SSH, and SV profile set. RAWX revision 35 and the RAW
revisions share one electrical mapping. The CGMES and XIIDM readers index
their records once, so a read scales with the model. The format guide lists
the mapped records and diagnosed limits.

UCTE-DEF revisions 2003.09.01 and 2007.05.01 parse and emit, with fresh
output using 2007.05.01. IEEE Common Data Format is a read-only input.
PowerWorld PWB remains read only and recognizes the bus and generator record
families covered by the binary corpus.

BMOPF parsing accepts schema 0.1.0 and 0.2.0, resolving the profile from
`meta.schema_version` or `meta.$schema`, and returns a
`MulticonductorNetwork`; callers construct `McAcPfInstance` or
`McAcOpfInstance` explicitly. Fresh output uses schema 0.2.0 from the
`distribution-system-opt/dsopt-schema` repository.
