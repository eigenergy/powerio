# PowerIO 0.11.0 release notes

PowerIO 0.10.0 was the public beta for the candidate 1.0 API. PowerIO 0.11
ships the architecture that came out of it, without declaring the Rust API
stable yet. Rust, Python, Julia, and C now share the same operations and the
same names for power system data.

The release stays pre-1.0 because public Rust signatures expose `sprs::CsMat`
and `petgraph::UnGraph`, and those crates are themselves pre-1.0. The 0.11.x
line is for compatible bug fixes, performance improvements, and additive work;
if a breaking public API change becomes unavoidable, it goes to 0.12. A 1.0
will follow a downstream stabilization cycle and an explicit decision about
those dependency boundaries.

## One module model

Parsing returns `PioModule<T>`, which holds one typed value together with its
diagnostics, producer, sources, source mappings, history, and extensions. The
registered values include balanced and multiconductor networks, operating
points, time series, scenario sets, power flow and optimal power flow
instances and solutions, and SCUC instances and solutions.

To find out what you have, match the enum `module.value()` returns in Rust,
use `isinstance` on `module.value` in Python, dispatch on `PioModule{T}` in
Julia, or use the structural type names, predicates, and owner rooted typed
handles in C. `PioValueKind`, `.kind`, and the typed narrowing wrappers are
removed.

`TimeSeries<T>` and `ScenarioSet<T>` are ordinary collections now, and the
selection and export API from 0.10 is removed.

## Parse, emit, serialize, deserialize

Every source enters through `parse`. Rust takes a file or directory name,
content in memory, or a built `Source`; C builds a `PioSource`; Python accepts
a path, file object, or bytes-like object; Julia dispatches on a path string,
`IO`, or `AbstractVector{UInt8}`.

`emit` produces grid exchange formats and returns an `EmitResult`: the
artifacts it produced (one per file, each with its name and either its bytes
or its path), the output layout, the fidelity (an exact same format echo of
retained source bytes, or canonical fresh output), and the emission
diagnostics. The same call handles memory, single file, and directory output.
PowerIO IR goes through `serialize` and `deserialize` instead and does not
appear in grid exchange format discovery.

PowerIO IR is also the only JSON document PowerIO owns. The old bare
`BalancedNetwork` JSON methods and the `model-json` classifier family are
removed; to write a network, wrap it in a `PioModule` and pass it to
`serialize`.

Emitting a calculation instance writes its electrical network and diagnoses
the calculation fields the target cannot carry. Emitting an AC power flow or
OPF solution also writes the bus voltages, generator dispatch, and branch
terminal flows the target supports, and diagnoses objectives, multipliers,
termination data, residuals, and any other result it cannot carry. An SOCWR
result is not written as if it were an AC solution: emission writes only its
instance network and diagnoses the relaxation values and objective lower bound
it left out.

The duplicate beta parse and write names are removed;
[From 0.10 to 0.11](../src/migration-0.11.md) has the complete list.

## Typed updates

`OperatingPointUpdate`, `NetworkUpdate`, and `CalculationUpdate` identify
components by stable `ComponentId` and carry absolute values with explicit
units. `apply_updates` validates the whole batch first and then applies it
atomically. `UpdateReport` lists every changed component and field and says
whether energized connectivity changed.

The first update set covers load active and reactive power, generator
setpoints and service status, branch thermal ratings and service status,
transformer tap and phase shift, and switch position. A bus demand command
has to name a load or an explicit allocation rule.

## DC calculations

The public DC data bundles and the phrase “DC branch coefficients” are
removed. Public matrices and vectors use their PowerModels and MATPOWER names:

```text
calc_incidence_matrix
calc_branch_susceptances
calc_bus_susceptance_matrix
calc_branch_flow_matrix
calc_branch_phase_shift_injection
calc_bus_phase_shift_injection
calc_branch_flow_dc
calc_bus_injection_dc
```

The incidence matrix is branches by buses with `+1` at the from bus and `-1`
at the to bus. Phase shift injections stay separate. The matrix guide has the
complete signs and equations.

## Calculation results

`SocwrOpfSolution` holds the W-space values, generation, terminal powers,
duals, termination, and objective lower bound from a PowerModels SOCWR
relaxation. PowerIO does not label that result `AcOpfSolution` without checked
voltage recovery and AC residual validation.

Economic outputs describe derivatives of the declared objective. Bus active
and reactive demand marginals and the two nonnegative branch thermal limit
multipliers replace the ambiguous beta price and signed branch dual fields.

## GridFM fidelity

GridFM Parquet reads keep the branch terminal flows and fixed quadratic
generator costs the dataset gives. Dense bus indices, nodal load and shunt
totals, and unit tap line classification are how GridFM natively represents
things, so the reader no longer warns about them. On the way out, GridFM
output reports the projections it actually performs from a richer source
network, and an unchanged GridFM dataset writes without findings. PowerIO IR
records which component identities PowerIO generated, so writers can tell
stable internal references from source metadata. Batch output checks that
scenario ids are unique and that the system base and the bus, branch, and
generator row identities line up.

## PowerIO IR

The serializer and deserializer use `"schema": "pio-ir"` with integer
`"version": 2`. That integer is the PowerIO IR generation, and it changes only
when the serialized representation changes. The producer record names the
PowerIO release separately (`0.11.0` here), and C ABI 7 is numbered
independently of both. Source bytes retained at runtime are not serialized. A
document with an unsupported identity or generation is refused, and the error
says what the reader found.

`docs/schema/README.md` keeps the PowerIO IR history in one place. The `0.1`,
`0.2`, and `0.9` schemas from the retired `powerio-pkg` crate and the v0.10.0
`powerio.module` schema are archived there as documentation only, all under
the single `pio-ir` archive; none of the retired payload schemas is part of
the current representation.

## C ABI 7 and Julia

PowerIO 0.11 ships C ABI 7. It uses opaque reference counted handles, explicit
buffer lengths, one structured error channel, structural type names, and typed
borrowed access that does not encode the module value. ABI 4, 5, and 6
symbols are not present.

PowerIO.jl builds on ABI 7 and gives you Julia structs, multiple dispatch,
natural indexing, and mutating functions ending in `!`. It is the supported
Julia binding, so Julia code goes through it rather than calling the C ABI
directly.

## Interoperability

The 0.11 format layer adds XIIDM, JIIDM, CGMES, and PSS/E RAWX support.
PSS/E RAW revisions 32 through 35 are accepted; revision 32 is read only, and
fresh output uses revisions 33 through 35. XIIDM and JIIDM are the XML and
JSON encodings of the IIDM model; versions 1.0 through 1.17 are accepted and
fresh output uses 1.17. CGMES 2.4.15 and 3.0 are accepted, and fresh output is
a deterministic 3.0 EQ, TP, SSH, and SV profile set. RAWX revision 35 shares
one electrical mapping with the RAW revisions. The CGMES and XIIDM readers
index their records once, so a read scales with the model. The format guide
lists the mapped records and diagnosed limits.

UCTE-DEF revisions 2003.09.01 and 2007.05.01 parse and emit, with fresh
output using 2007.05.01. IEEE Common Data Format is read only. PowerWorld PWB
is still read only, and it recognizes the bus and generator record families
the binary corpus covers.

BMOPF parsing accepts schema 0.1.0 and draft BMOPF 0.2,
checks agreement between `meta.schema_version` and `meta.$schema`, and returns a
`MulticonductorNetwork`. Calculation instances are constructed separately.
BMOPF 0.2.0 remains subject to Task Force review; PowerIO does not declare it
ratified or create a `schema-v0.2.0` tag.

Fresh proposal output identifies immutable proposal commit
`fe8671a74d2fc1a15a499c5b1f66cbb80fc22e12` and records its SHA-256 schema digest
in producer provenance. Known earlier identifiers remain documented aliases.
Explicit schema-version selection produces the requested schema version, including reported
legacy relocations; ordinary same-format emission preserves retained source
bytes. Rust, CLI, Python, C, Julia and MCP expose the same schema-version choice.

Unequal phase voltage bounds remain ordered vectors through conversion,
generation-2 IR and typed bindings. The unreleased ABI 7 bus view includes these
vectors with owner-rooted borrowing. Consumers must rebuild against the final
0.11 header and matching Julia binding. Transformer no-load admittance can state
its physical winding and per-coil SI values explicitly. Independent OpenDSS
comparisons check its location, phase scaling and tap scaling. Retained equipment
data does not imply computational support: matrix construction rejects required
physics outside its declared formulation.

The [field mapping](../src/bmopf-field-mapping.md),
[proposal conformance packet](https://github.com/distribution-system-opt/dsopt-schema/blob/fe8671a74d2fc1a15a499c5b1f66cbb80fc22e12/docs/conformance.md),
and paired specification proposal document compatibility, intentional validation
rejections and computational limits.

### Final distribution integration

Burhan Abdullah's electrical-readiness PR #494 provides the shared structural
checks. Instance construction and multiconductor admittance assembly enforce
them. Unresolved OpenDSS geometry remains an untyped source object, and the
reader reports an error instead of creating guessed impedance or terminal data.
Unmodified same-format source emission remains byte-exact. Canonical conversion
from such incomplete data is intentionally rejected.

Draft BMOPF 0.2 output uses `energy_cost_rate` in $/kWh; the reader also accepts
legacy `cost`. Source and generator prices follow the per-phase ordering in Matt Deakin's
source/objective proposal. Optional IBR prices use that same ordering. Typed source prices survive IR and C/Julia views.
The proposed naming and objective conventions follow the Task Force's ongoing
source/objective discussion; this release does not ratify BMOPF 0.2.
