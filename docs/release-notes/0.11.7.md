# PowerIO 0.11.7 release notes

PowerIO 0.11.7 adds AC optimal transmission switching, carries HVDC lines
into power flow and DC OPF data, reads GridLAB-D feeders, reads more of
PSS/E (VSC DC lines, shunt FACTS devices, RAWX impedance correction tables,
and the reactive power of two-terminal converters), and keeps much more of a
case on a trip between PSS/E and PowSybl IIDM. C ABI 7 and PowerIO IR version 2 stay as they were;
everything new is an addition. Some defaults change, listed under
[Behavior changes](#behavior-changes). PowerIO.jl follows this release with
the same tested binary artifacts.

The [curated changelog](../../CHANGELOG.md#0117) gives each change in full.

## What is new

### AC optimal transmission switching

`AcOtsInstance` is an AC OPF problem plus switching options: which branches
may switch, what opening and closing each one costs, whether islands may
split, limits on how many branches open or change state, and branch current
limits. PowerIO does not solve it. It checks a final topology and prices it
(`validate_topology`), builds the AC OPF over that topology for your solver
(`fix_topology`), and attaches the solver's answer as an `AcOtsSolution`
after checking that the answer solves that exact problem and that open
branches carry no flow. `materialize_ac_ots_solution` gives back the network
with the final statuses and solved values, which is the thing to write with
`emit`.

The workflow is available in Rust, in PowerIO IR, in Python
(`PioModule.to_ac_ots_instance(...)`, `AcOtsInstance`, `AcOtsSolution`), in
the C ABI (`pio_ac_ots_*`), and in PowerIO.jl.

### HVDC

- HVDC lines now count in power flow instances and DC OPF preparation as
  fixed injections at their terminal buses. Before, they were left out, so a
  DC line's scheduled transfer did not appear in the bus balance.
- `Hvdc::calc_bus_to_device_powers` is the one place that turns the stored
  MATPOWER `dcline` signs into terminal powers measured from each AC bus into
  the HVDC system. The stored fields keep their signs throughout 0.11.x.
- The PSS/E and RAWX readers read VSC DC lines instead of skipping them, and
  the writers write them back.
- `Hvdc::calc_lcc_operating_point` computes a two-terminal (LCC) line's DC
  current, firing angles, and converter reactive power from the PSS/E bridge
  equations. PSS/E files do not state that reactive power, so this fills the
  gap at analysis time. Nothing new is stored.

### PSS/E and other transmission formats

- Shunt FACTS devices (STATCOMs) read as static var compensators and write
  back as FACTS records, in RAW and RAWX.
- Impedance correction tables keep every point when a table spans
  continuation lines, and an impedance you edit after applying a correction
  is written correctly. RAWX now reads and writes the tables too (the
  `impcor` table); before, RAWX transformers read uncorrected.
- TARA contingency statements that name buses and branches by name, and
  dispatch and participation rules, can be resolved against a network.
- `SharedPsseEquipmentIndex` builds the PSS/E equipment index once and keeps
  it beside the network.
- Writing Surge JSON now reports the three-winding transformers it has to
  drop, instead of dropping them silently.
- A four-value `MONITOR VOLTAGE RANGE` line in a `.mon` file now gets a
  remark (`READ.MON.VOLTAGE_BAND_ORDER_ASSUMED`). PowerIO reads the first
  pair as the post-contingency band and the second as the pre-contingency
  band, as before, but no public source confirms that order, so the remark
  tells you to check it against the tool that wrote the file. The values are
  unchanged. The PSS/E 35.2 spelling `IN KVRANGE lo hi` is now read too.

### PowSybl IIDM and PSS/E

A case now keeps much more on a trip between PSS/E and XIIDM or JIIDM, and
what it cannot keep is reported:

- **Node numbering.** A node-breaker IIDM case writes RAWX and RAW 34 and 35.
  IIDM numbers nodes from 0 in each voltage level, so such cases failed; a
  substation with repeated or nonpositive node numbers is now renumbered
  from 1, as PowSybl does, with a diagnostic.
- **Ratings.** IIDM current limits become PSS/E MVA ratings
  (`sqrt(3) * Vnom * I / 1000`) instead of reading as unlimited.
- **Bus identity.** The writers name a bus `B<n>` with its PSS/E name as the
  IIDM name, as PowSybl's importer does, and the readers take both back, so
  bus 10 no longer comes back as bus 5.
- **Slack terminal.** A reference bus that hosts only branches stays the
  reference; the writers now name a slack terminal there.
- **Tap control both ways.** A PSS/E winding control (COD 0 to 3) becomes an
  IIDM ratio or phase tap changer, and an IIDM tap changer reads back as the
  same COD, CONT, RMA, RMI, VMA, VMI, and NTP.
- **Zones, owners, and areas.** Bus zone and owner and an area's swing bus
  and interchange tolerance travel as IIDM properties (`psse_zone`,
  `psse_owner`, `psse_isw`, `psse_ptol`).
- **Three-winding transformers.** The star-point voltage, each leg's
  in-service status, and ratings past rate C survive the trip.
- **Storage.** An IIDM battery is written to PSS/E as a load that consumes
  what it injects, as PowSybl's exporter does, instead of being dropped.
- **Reported changes.** PSS/E output now reports a DC line whose power the
  record cannot reproduce, a dropped case date, and an area read back as a
  control area. These were the only conversion matrix cells where the data
  changed without a finding.

### Balanced networks and sensitivities

- `calc_stated_state_mismatch` (`powerio verify --stated-state`) checks a
  saved case's AC bus balance at its own stored voltages and outputs, flags
  the equipment a residual usually comes from, and ranks the worst buses. A
  case saved from a converged solution should close to rounding, so the
  residual shows where PowerIO reads equipment differently from the program
  that solved it.
- PTDF and LODF work with series capacitors (negative reactance) on the
  sparse path, so large cases with them no longer need the dense path. You
  can also ask for selected PTDF rows or columns, or LODF columns, without
  building the whole matrix, and get one PTDF per island with
  `calc_ptdf_by_island`.
- Per-island reference assignment (`assign_island_references`) now demotes
  a reference bus with no in-service generator and picks the bus of the
  island's largest generator (by `pmax`), so an island can no longer keep a
  reference with nothing behind it, and the raw call and normalization pick
  the same bus.
- Bus merges keep the tightest voltage limits of the merged buses and report
  conflicting limits or reference angles.
  `BalancedNetwork::de_energize_buses` and `keep_island` expose the island
  handling that reference assignment already used.
- The synthetic test network generators now live in their own crate,
  `powerio-synth`. `powerio-matrix::synth` and `powerio gen` work as before.

### Distribution: GridLAB-D, OpenDSS, and CIM

- GridLAB-D `.glm` feeders read to and write from `MulticonductorNetwork`,
  with the PNNL 5.3 profile (`gridlabd`, the default for `.glm`) and the
  Arras 4.3 profile (`gridlabd-arras`). An unchanged project writes back byte
  for byte, includes and all. The supported profile is static: fixed sources,
  lines and conductor geometry, loads, switches, transformers and fixed
  regulators, services, and fixed solar, generator, and battery outputs.
  Controls are kept as source text or refused; PowerIO never runs the
  simulator. The IEEE 4, 13, 34, 37, 123, and 8500 feeders are checked against
  both GridLAB-D forks and OpenDSS.
- OpenDSS imports keep the source impedance, the order of line definitions,
  conductor geometry, transformer templates, and static device states, and
  the canonical OpenDSS writer reproduces them with exact equivalent
  circuits.
- OpenDSS load voltage bands and low-voltage dropout are kept (see below).
- Distribution CIM reads and writes the transformer tank form used by
  GridAPPS-D and CIMHub feeders, opens out-of-service switches, and refuses
  inactive or disconnected equipment it cannot represent instead of
  energizing it. Format discovery now names the release and profile
  ("CIM100 cim17v40, GridAPPS-D profile"), and the distribution guide states
  what is validated and what is not mapped yet.
- PowerModelsDistribution engineering JSON with several time steps (PMD's
  `make_multinetwork` output) now reads as a `TimeSeries` of networks, one
  per step, instead of an empty network. The PMD writer writes back the
  `time_series` section and the components' references to it.
- Component locations from GridLAB-D pass through PowerIO IR.
- Two-terminal delta capacitor banks get their full rated reactive power in
  the multiconductor admittance; before, it was halved. The IVR OPF
  preparation stamps the same value.
- The IVR OPF preparation finds its transformer start voltages with a sparse
  solve. On a 2,000-terminal feeder this takes under a millisecond instead of
  about a second and 24 MB, and large feeders no longer need gigabytes. The
  start values are unchanged.
- Writing an unchanged OpenDSS project still copies every supplied file, and
  now a remark (`EMIT.DSS.PROJECT_COMPANION_KEPT`) names the files the deck
  never read.

### SINCAL

The SINCAL readers do less repeated work on large projects, stop reading an
oversized table as soon as it passes its limit, and report profile tables as
source-only when no snapshot used them. The balanced reader now reads a line
whose `Line.fr` is not 1, scaling its current limit and thermal rating by
`fr` as the multiconductor reader does; before, such a line was refused.
`SincalContainer::archive_with` takes an `ArchiveOptions` struct for `.sinx`
packaging. A 1,000-line feeder on the full native schema reads in about
0.3 s.

### Bindings

- C ABI 7 adds the AC OTS entry points, `pio_balanced_network_islands`
  (islands with their buses, references, generators, and HVDC ties),
  `pio_calc_sensitivities` (PTDF and LODF from the same Rust routine Python
  uses), and complete views of bounded distribution load laws
  (`pio_multiconductor_network_load_details_at` and the PF instance
  equivalents). No existing struct or function changes.
- Python adds the AC OTS classes, `calc_stated_state_mismatch` and
  `calc_stated_branch_flows`, and keeps structured diagnostics on parse
  errors.

### PowerIO Convert

[PowerIO Convert](https://powerio.dev/convert/) converts batches of files in
the browser, including project folders and ZIP files with mixed formats. The
conversion runs locally in WebAssembly; files are not uploaded, and sending
error statistics is optional.

## Behavior changes

- **Ordinary OpenDSS loads read as voltage-bounded laws.** OpenDSS loads
  default to `model=1`, which switches to constant impedance outside a voltage
  band. PowerIO now keeps that band (and ZIP dropout) instead of reading a
  plain constant-power load. The multiconductor IVR OPF preparation and the
  strict LinDist3Flow mapping refuse a bounded law by default, so an ordinary
  OpenDSS feeder that built before now needs an explicit choice: set
  `BoundedLoadLawPolicy::ProjectToNominal` on `McAcOpfAssemblyOptions`, or use
  the `approximate` or `permissive` LinDist3Flow `unsupported` policy. Either
  one uses each load's nominal law and reports it
  (`BUILD.MULTI.LOAD_LAW_PROJECTED`, `load_approximated`). The older C load
  views refuse a bounded law; use the new `*_load_details_at` views.
- **OpenDSS switches.** A line with `switch=y` reads as a closed 1 mOhm line.
  A SwtControl's `Action` and `Normal` are controller settings and no longer
  open or close anything in the fixed circuit; PowerIO warns
  (`READ.DSS.RETAINED_SOURCE_ONLY`), and `net.switches()` is empty for such
  files. An explicit `State=` on a SwtControl, or an `Open` or `Close`
  command, is refused with `READ.DSS.LINE_UNRESOLVED`. Before, SwtControl
  state produced typed open and closed switches.
- **HVDC lines inject power by default.** `DcPfInstance`, `AcPfInstance`,
  and DC OPF preparation built from a network now include each in-service
  HVDC line as fixed injections, so results for cases with DC lines change.
  `HvdcTreatment::Ignore` (or `powerio dcopf --hvdc ignore`) gives the old
  result. The stored `pf`, `pt`, `qf`, and `qt` fields keep MATPOWER's
  `dcline` signs; read terminal powers through
  `Hvdc::calc_bus_to_device_powers` rather than reinterpreting the fields.
  The C `pio_build_dc_opf_preparation` still leaves HVDC lines out, AC OPF
  preparation does not include them yet, and GridFM output reports them as
  omitted.
- **AC OTS islanding.** Under `forbidden`, a topology may not split any
  island of the starting network; a starting network that already has
  several islands is fine. Under `allowed`, islands may split. Under either
  policy, a topology that leaves buses that had a generator in an island
  with no generator is refused, because PowerIO does not shed load.
- **PTDF and LODF refuse closed switches.** Merge them first; normalization
  does by default. The stated-state check refuses them the same way.
- **The conversion matrix grades cells by fidelity.** Each cell shows its
  worst finding: exact, lossless, restated (the target needed a value and
  the writer supplied it), approximate, dropped, or failed. The diagonal
  checks byte-exact round trips. The expected results are a plain text file,
  `powerio-cli/tests/conversion_matrix.baseline`. Every cell that changes
  the data now has a finding.
- **Per-island reference choice.** When two generators tie on `pmax`, the
  one on the smaller bus id becomes the reference (normalization used to
  take the earlier generator row), and a stated reference with no in-service
  generator is demoted. `Island::calc_reference_choice` returns `None` for an
  island no in-service generator supplies.
- **PSS/E to IIDM output.** Buses are named `B<n>` instead of
  `powerio-bus-<n>`, tap changers, slack terminals, and PSS/E zone, owner,
  and area properties are written, and storage reaches PSS/E as a load. The
  readers still accept the older `powerio-bus-<n>` ids.
- **PMD multinetwork files** parse to `TimeSeries<MulticonductorNetwork>`;
  the single-network reader refuses them with a message saying so.

## Compatibility

- **C ABI 7 is unchanged.** 0.11.7 adds entry points and structs; no
  existing layout, function, or meaning changes.
- **PowerIO IR stays at version 2.** The 0.11.7 schema,
  `pio-ir/2/0.11.7/schema.json`, adds `powerio.AcOtsInstance`,
  `powerio.AcOtsSolution`, the `branch_switching_cost` objective term,
  `powerio.LocatedMulticonductorNetwork` for networks with component
  locations, bounded load laws (`bounded_zip`, `bounded_constant_power`,
  `bounded_exponential`), and one optional field, `hvdc_treatment`, on DC
  and AC power flow instances. That field is written only for
  `fixed_injection`; an instance that ignores HVDC writes exactly what earlier
  releases wrote, and a document without the field reads as `ignore`, the
  calculation it meant when it was written. Published schemas keep their
  exact bytes.
- **Readers before 0.11.7 reject documents that use the new types,** fields,
  or variants, rather than read them wrongly. Every document an earlier
  release wrote still reads.

## Upgrading

- **Python:** `pip install -U powerio`. Nothing is removed. If you build
  multiconductor OPF or LinDist3Flow data from OpenDSS feeders, choose a
  bounded load policy as described above.
- **Julia:** PowerIO.jl publishes its 0.11.7 release on its own once this
  release is out; update with `Pkg.update("PowerIO")`. It binds the new AC
  OTS, island, sensitivity, and load-law entry points.
- **Rust:** the new `powerio-synth` crate is published alongside the others.
  If you build power flow instances or DC OPF data from cases with HVDC lines
  and want the earlier numbers, pass `HvdcTreatment::Ignore`.
- **C:** existing code keeps working against ABI 7. Code that reads
  OpenDSS loads through the older load views should move to the
  `*_load_details_at` views, since ordinary OpenDSS loads are now bounded.

## Known limits

- AC OPF preparation and the C DC OPF preparation do not carry HVDC
  injections yet.
- The PSS/E two-terminal reader and the new LCC model compute the DC current
  differently; the reader is unchanged in this release, since aligning it
  would change conversion output.
- GridLAB-D support is the static profile only. Four edited IEEE 9500
  delta-grounded-wye source cases are refused rather than written.

## Release validation

Source CI, native Python wheels and smoke tests, and paired Julia source tests
run before the release tag. The tag workflow then runs PowerIO.jl against all
five packaged C library archives before it creates a draft. Publication and
the protected registry approvals are separate steps; passing source checks
alone does not mean a package has been published.
