# PowerIO 0.11.6 release notes

`powerio-tnd` replaces the unreleased SINCAL support crate. See the
[integration guide](../src/tnd.md) for composition, adapter migration, and the
Rust-only API scope.

PowerIO 0.11.6 corrects numerical interpretation and preserves more explicit
network structure. Several of these corrections change results by default,
listed below. C ABI 7 layouts and PowerIO IR version 2 are unchanged.
PowerIO.jl accompanies the native release through the same tested binary
artifacts.

## Changed results

- Normalization merges the buses that closed switches join
  (`ClosedSwitchPolicy::Merge`, the new default), so a case with closed
  switches normalizes to fewer buses and smaller matrices. A merge it cannot
  complete fails with `BUILD.SWITCH.CLOSED`; `ClosedSwitchPolicy::Keep` keeps
  the switches as data, as before.
- Closed switches count as connections for islands, reference coverage,
  radiality, connectivity reports, and isolated-bus retyping.
- `merge_zero_impedance_buses` rewrites every element reference, gives the
  survivor the strongest bus kind of its group, folds removed branches'
  charging onto it, and no longer merges across an off-nominal ideal
  transformer. `reduce_zero_impedance` shares the same merge.
- PSS/E loads read `YQ` with the PSS/E sign and net out distributed
  generation; revision 34 node columns sit where PSS/E 34 writes them; the
  two-winding magnetizing admittance reaches bus I; three-winding
  transformers keep each winding's status and all twelve ratings.
- `DcOperators::update` refuses operators built for a network that has since
  changed, and `serialize` refuses a collection larger than `deserialize`
  accepts.

The [curated changelog](../../CHANGELOG.md#0116) gives each change in full.

## Correctness and safety

- MATPOWER's bounded post-literal demand and impedance conversions now apply.
  This fixes case33bw's kW-to-MW and ohm-to-per-unit interpretation. Unsupported
  or ambiguous code still produces source-span warnings rather than guessed
  execution. Unchanged source echo remains byte-exact; canonical and
  cross-format output use the corrected values.
- PSS/E transformer impedance correction tables preserve their units and
  nominal impedances, so repeated application is idempotent. Partial
  three-winding service states, winding ratings, island cuts, and row provenance
  remain consistent through lowering and normalization.
- Partial three-winding states use a distinct nested IR record. Older readers
  reject that record instead of silently energizing a disconnected winding.
  Ordinary legacy all-on/all-off transformer records retain their published layout.
- Multiconductor PF/OPF construction rejects physical islands without a voltage
  source rather than implicitly anchoring them. Parsing retains those devices;
  callers must resolve de-energized islands explicitly before construction.

Reparse original MATPOWER/PSS/E inputs to obtain corrected values when an older
stored document contains a previous interpretation. These correctness changes
can intentionally change numerical results or reject an unsafe preparation
that an older release accepted. The reverse direction is not safe either:
write PSS/E from a document 0.11.6 produced with 0.11.6 or later. The 0.11.5
PSS/E writer would flip the constant-admittance load sign, subtract
distributed generation a second time, and write the magnetizing admittance
multiplied by the square of the tap.

## Additive capabilities

- Caller-supplied in-memory file trees support referenced OpenDSS and PyPSA
  inputs, retaining source paths and exact unchanged output.
- Explicit SINCAL electrical profiles read supported balanced and
  multiconductor snapshots, including selected drawing geometry. A separate,
  explicitly experimental writer covers a bounded static subset. It is not
  enabled by default; native desktop acceptance and writer binding options
  remain separate work.
- Distribution CIM uses the explicit cim-dist profile, with diagnostics and
  refusal for unsupported electrical data rather than fabricated impedances.
- Referenced multiconductor voltage sources preserve both voltage endpoints.
  Floating-neutral transformer constraints and solver-independent AC IVR
  preparation extend the supported electrical models without adding a solver.
- Explicit angle-difference policies preserve the default PowerModels padding
  while allowing stated or unbounded limits. Island subsets expose consistent
  source-to-result row maps.
- PSS/E `.dyr` files parse to a loss-preserving `DynamicCase`, and
  `DynamicStudy` pairs one with its network. This is a Rust-only API for now.
- `.mon` files read kV-qualified subsystem scopes and four-value voltage bands
  with separate pre-contingency limits.

## Compatibility and known limits

C ABI 7 and IR version 2 are unchanged, and frozen published schemas retain their
exact bytes. The 0.11.6 schema catalog adds the `cim-dist` and `sincal` source
formats, the kV-qualified monitor scope and statement kinds, and fail-closed
structural alternatives for referenced sources and partial three-winding
transformers. Older readers can still read the ordinary legacy records, but
intentionally reject new representations they cannot interpret faithfully.
Reading a stored multiconductor PF or OPF instance applies the same check as
construction, so a 0.11.5 document whose instance has an island without a
voltage source no longer loads.

The inert C-API Cargo feature arrow remains as a deprecated compatibility alias
for existing source-build scripts. Maintained callers use the actual feature
tuple matrix,gridfm,dist,prob. Its eventual breaking removal is tracked in
[issue #673](https://github.com/eigenergy/powerio/issues/673); it never enabled
Arrow C-API output. The real GridFM dependency remains unchanged.

Native SINCAL support compiles SQLite and is the default-on Cargo feature sincal
of powerio, enabling powerio-tnd/sincal; the CLI, Python wheels, C library and
browser converter include it. A Rust consumer that sets default-features = false
builds without SQLite, so a wasm32-unknown-unknown build needs no C compiler.
Such a build lists no SINCAL format and refuses SINCAL input or output with
REQUEST.SINCAL.FEATURE_DISABLED.

The SINCAL multiconductor reader shares a fixed SQLite work budget across a
parse and reads feeders of up to roughly 450 lines; a larger project fails with
a message saying so rather than producing partial output.

Two known gaps remain in this release. Converting a case with three-winding
transformers to Surge JSON drops them without a diagnostic
([issue #686](https://github.com/eigenergy/powerio/issues/686)). The cim-dist
reader carries equipment the source marks out of service or disconnected in
service, with a warning, so an open switch stated that way still joins its
islands ([issue #687](https://github.com/eigenergy/powerio/issues/687)).

Julia's existing three-winding row in_service field is device-level only; typed
per-winding status access remains follow-up work. Use the native lowering and
matrix APIs for partial-winding topology. Existing ABI structs are not enlarged.

The planned converter portal, broader HVDC/RAWX work, AC optimal transmission switching,
and other deferred features are not part of this release cut.

## Release validation

Source CI, native Python wheels and smoke tests, and paired Julia source tests
precede the release tag. The tag workflow then runs Julia against all five
packaged C-library archives before creating a draft. Publication and protected
registry approvals remain separate steps; successful source checks alone do not
mean a package has been published.

The [curated changelog](../../CHANGELOG.md#0116) records the detailed changes.
