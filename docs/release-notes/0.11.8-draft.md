# PowerIO 0.11.8 release notes

PowerIO 0.11.8 is a correction release. It fixes two defects in the
multiconductor IVR OPF preparation and repairs release validation. The
`v0.11.7` tag was cut before these fixes merged, so a consumer that needs them
must require 0.11.8. C ABI 7, PowerIO IR version 2 and the IR schema snapshot
`pio-ir/2/0.11.7` are unchanged; everything new is an addition.

The [curated changelog](../../CHANGELOG.md#0118) gives each change in full.

## Multiconductor IVR OPF preparation

- **Fixed power factor without loss of small values.** Preparation now
  carries bounded coefficients `(a, b)` for each fixed-PF coil, so the row is
  `a·P + b·Q = 0` with `a = sqrt((1 - |pf|)(1 + |pf|))` and `b = pf`. Before,
  consumers could only read the slope `tan(acos(|pf|))`, which overflows as
  `|pf|` approaches 0 and loses the sign of tiny PF values. The slope is still
  reported when it is finite. Its absence does not mean the coil has no PF
  control, so consumers should assemble the row from
  `power_factor_coefficients`.
- **Delta terminal roles.** A DELTA coil, a THREE_LEG inverter or a DELTA
  transformer winding whose terminal map includes a neutral or earth terminal
  is now refused during preparation. Before, a DELTA load on `[a, b, n]` built
  a solvable model of a connection the case did not describe.

## Release validation

Foreign time-series controls stay verbatim under BMOPF extras instead of
being read as multiplicative profiles. Every snapshot of a PMD multinetwork
fixture is validated. The Julia companion pin is removed now that the
bindings it waited for have merged.

## Upgrading

No code changes are needed. Consumers of the MC IVR preparation that build
fixed-PF rows should switch from `reactive_slope` to
`power_factor_coefficients`. Cases with DELTA devices connected to a neutral
now fail preparation with a diagnostic and should be corrected in the source
data.
