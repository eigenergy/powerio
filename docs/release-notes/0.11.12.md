# PowerIO 0.11.12 release notes

PowerIO 0.11.12 is a patch release of conversion fixes. XIIDM and JIIDM
output no longer keep an `activePowerControl` or `slackTerminal` extension
for equipment that could not be written, which made PowSybl reject the file.
pandapower piecewise costs now start where pandapower starts them, so a curve
whose first point is not at zero power keeps its native cost. Python table
getters read only the table they are asked for, which also fixes reading the
tables of a distribution network that carries coordinates. C ABI 7, PowerIO
IR version 2 and the IR schema `pio-ir/2/0.11.8/schema.json` are unchanged.
PowerIO.jl follows this release with the same tested binary artifacts.

The [curated changelog](../../CHANGELOG.md#01112) gives each change in full.

## What is new

### XIIDM extensions name only equipment the file contains

XIIDM and JIIDM state a generator's or battery's active power control, and a
voltage level's slack terminal, in extensions that refer to equipment by its
id. With partial substation data, PowerIO 0.11.11 can leave a generator,
battery, or branch out of the file and report it as
`EMIT.XIIDM.RECORD_DROPPED`, but it still wrote the extension that refers to
it. PowSybl rejects a file whose extension names absent equipment. The
writer now leaves such an extension out and reports the lost field as
`EMIT.XIIDM.FIELD_DROPPED` (or `EMIT.JIIDM.FIELD_DROPPED`) next to the
equipment's own report (#837, #839).

### pandapower piecewise costs keep their native starting cost

pandapower's `pwl_cost` table gives a curve as power ranges and marginal
slopes, and pandapower's objective starts the curve at the first power times
the first slope. PowerIO started every curve at zero cost instead. A curve
`[[10, 20, 5]]`, for example, costs 50 at 10 MW in pandapower and 0 in
PowerIO 0.11.11, so every cost in a converted network was shifted by that
amount when the first power was not zero. The reader now keeps pandapower's
starting cost. The writer reports a lost constant term only when the curve
really differs from that start, not whenever the first cost is nonzero
(#840).

### Python table getters read only the requested table

A table getter such as `network.buses` or `network.hvdc` used to convert the
whole network to PowerIO IR and then pick one table out of it. That was slow
for a small table on a large case, and it failed for a distribution network
with coordinates, where the IR document nests the network one level deeper:
`network.buses` raised a missing-field error. Each getter now converts only
its own table. The rows, their shapes and the string spelling of nonfinite
numbers are unchanged (#842).

### Smaller changes

The validation oracles and the `bench` extra use pandapower 3.5.6 instead of
3.2.2 (#851).

## Behavior changes

- XIIDM and JIIDM output leave out an `activePowerControl` or `slackTerminal`
  extension whose equipment is not written, and report
  `FIELD_DROPPED`. 0.11.11 wrote the extension, and PowSybl rejected the
  file.
- A pandapower network read from `pwl_cost` reports a different (now native)
  cost for a curve whose first power is not zero. Costs of curves starting at
  zero power are unchanged.
- Python table getters on a distribution network with coordinates return the
  table instead of raising.

## Compatibility

C ABI 7 and PowerIO IR version 2 are unchanged, and IR documents keep naming
the `pio-ir/2/0.11.8/schema.json` catalog. No public item is renamed or
removed. The minimum supported Rust version stays 1.89 and the minimum
Python version stays 3.11.

## Release validation

Source CI, native Python wheels and smoke tests, and paired Julia source tests
run before the release tag. The tag workflow then runs PowerIO.jl against all
five packaged C library archives before it creates a draft. Publication and
the protected registry approvals are separate steps; passing source checks
alone does not mean a package has been published.
