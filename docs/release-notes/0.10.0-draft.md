# PowerIO 0.10.0 release notes (draft)

PowerIO 0.10 is the public beta of the 1.0 API. API corrections may land before 1.0.0 as downstream integrations exercise the new design.

Prepared by the release branch; the version bump, the tag, and the published notes are deliberate human steps. This draft states what 0.10.0 ships relative to 0.9.0, PR by PR, so the published notes are an edit rather than an excavation.

## The runtime and the stored document

`PioModule<PioValue>` is the one runtime unit: one typed value (balanced network, multiconductor network, balanced network time series, balanced operating point time series, or balanced network scenario set) with the common records (producer, sources, source map, diagnostics, descriptive history, namespaced extensions). `.pio.json` version 1 is its stored form: header dispatched, exactly typed, reference validated, byte stable, with `"Infinity"`/`"-Infinity"`/`"NaN"` spellings and `null` refused. Every released 0.9 package upgrades one way on read, with legacy operating points becoming the primary typed series and legacy element paths translated; a nonempty legacy study is refused with the materialize instruction. The generated JSON Schema is served under `schema/pio-module/1`.

## Typed state and transformations

`state_inventory`, `select_state`, and `export_state` are the typed time and scenario surface: selection returns the existing item with no clone and no serialization; export is the separate explicit materialization with the selection stated in history. The multiconductor to balanced lowering gains supported `wye_delta`/`delta_wye` transformers (zone voltage bases, ANSI thirty degree shift) and unrated identity closed switch merges with recorded bus and switch identities; refusals are coded, and no epsilon impedance is ever invented. `lower_module_to_balanced` carries records and source ownership across the transform.

## Matrices and problem data

Sensitivities factor once through a sparse Cholesky with measured memory evidence; DC operators, AC Jacobians, and multiconductor admittance land per the matrix stack. `dc_network_data` is the one DC branch data assembly (incidence endpoints, susceptance under a named formula, phase shift injection, stable element mappings, omissions with reasons), read identically from Rust, C, Python, and Julia.

## The C ABI (v6)

Owned handles with retain/release pairs, structured `PioError` handles, the stored module surface, and the DC branch data. The v5 entry points are unchanged; the 0.9 package handle stays single owner as the migration surface. Exercised from C under address and undefined behavior sanitizers, from Miri over the handle core, and from a Go client.

## Bindings

Python keeps PyO3 over the same Rust owners: `StoredModule`, `BalancedNetwork.dc_data`, `powerio.versions()`, and the MCP tools (inspect, state inventory and selection, export, lowering inspect and transform, DC data, about). Julia targets ABI v6 with `StoredModule`, `DcData` borrowed views that root their owner, typed records, assembled DC matrices, and the cross language vocabulary stated in the docs.

## Retirements

The pre 0.9 `.pio.json` lineage is refused (regenerate with 0.9). `TRANSFORM.MULTI_TO_BALANCED.UNSUPPORTED_CLOSED_SWITCH` and the CG sensitivity path's codes and knobs are retired. The names deprecated in 0.9 are removed: `scripts/deprecated-inventory.sh --assert-empty` runs in CI and passes, so 1.0.0 ships no deprecated entry.
