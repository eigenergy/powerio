# PowerIO 0.12.0-rc.1 release notes

PowerIO 0.12.0-rc.1 is the release candidate for 0.12, which starts the
0.12.x release series. From 0.12 on, the release series says what is
compatible with what: within 0.12.x, the public Rust, Python, and Julia APIs
only gain items, the C ABI only gains symbols, and newer readers keep reading
older IR documents. Older readers accept compatible documents for types they
support and refuse unknown structural types. A break to an existing type waits
for the next series.

Before 1.0, settle the exposed `sprs::CsMat` and `num_complex::Complex64`
compatibility contract, the conventions and reference/slack questions, and the
remaining public milestone scope. Pre-1.0 dependency versions do not inherently
prevent a stable PowerIO API; choosing to expose their types is a compatibility
commitment. See [the 1.0 readiness checklist](../src/known-limits.md#path-to-10).
This candidate already replaces `IndexedNetwork::to_petgraph` with the
PowerIO-owned `branch_edges()` interface.

This candidate removes the version numbers 0.11 carried beside the release,
retires the compatibility shims 0.11 kept, fixes the placement of a three
winding transformer's magnetizing admittance and two XIIDM sign conventions,
adds input collections for ZIP archives and folders of related files, and
raises cross format fidelity. [From 0.11 to 0.12](../src/migration-0.12.md)
lists everything that needs action. The
[curated changelog](../../CHANGELOG.md#0120-rc1) gives each change in full.

## What changes

### CGMES limits and tap-changer identity

Typed loading limits and branch ratings consistently prefer active values over
equipment defaults. Transformer current limits use the voltage of the terminal
carrying each limit, including the low-voltage winding. A differing equipment
default that canonical output cannot retain is diagnosed. Ratio and phase
tap-changer identifiers and names survive IR and canonical output, including
modules stored by older readers. Synthetic regressions cover both CGMES
versions, temporary limits, terminal ordering and legacy metadata.

### Sienna and Python interchange

Balanced modules read and write SiennaSchemas 0.1.0, 0.2.0, 0.3.0, and 0.4.0.
The native `powersystems-json` adapter reads PowerSystems data formats 4 and 5
and writes format 5. Pinned schemas and external consumers verify the adapters.
Python adds optional Sienna HDF5 bundles, PyPSA NetCDF/HDF5 transports (#107),
and TransitionZero source/sink plugins. Serialized modules retain companion
arrays and pipeline extensions with their declared interpretation. See
[Sienna exchange](../src/sienna.md) for version selection and fidelity limits.

### One version for the release, the C ABI, and PowerIO IR

0.11 stated three numbers: the release, PowerIO IR version 2, and C ABI 7.
The two integers only ever changed when a new release series began, so 0.12
replaces both with the release (#701).

- A PowerIO IR document's header states the release whose schema it
  follows, `"version": "0.12.0"`, described by
  `docs/schema/pio-ir/0.12.0/schema.json`. A 0.12.x reader accepts any
  0.12.z document for a supported structural type and every 0.11 document
  (`"version": 2`) with the meaning it had. Every release from 0.12 on publishes its own schema file; the 0.11
  files under `pio-ir/2/` keep their bytes.
- The C header states the release it was generated from, as
  `PIO_VERSION_MAJOR`, `_MINOR`, and `_PATCH`, and `pio_version_numbers()`
  reports the library's. A program compiled against release 0.12.Z works
  with any 0.12.x library at 0.12.Z or newer. `PIO_ABI_VERSION` and
  `pio_abi_version()` are gone. CI compares `powerio.h` with the latest
  release header in the same series.
- PowerIO.jl checks the library's release series instead of the ABI number,
  and refuses a library older than 0.12 without calling its `pio_version`,
  whose return type differs before 0.11.
- A prerelease such as this one states its core release, `0.12.0`, in the
  numbers and the IR header, and its whole version in `pio_version()`,
  `powerio::VERSION`, and `producer.version`.

### Three winding transformer magnetizing admittance

PSS/E connects `MAG1 + jMAG2` from winding 1's bus to ground, outside that
winding's ratio; IIDM and CGMES state each leg's admittance at the star
point. 0.11 placed every three winding magnetizing admittance at the star
point, so a PSS/E unit with an off-nominal winding 1 ratio was off by about
`|Ym|` in `Y_bus` (#741). `Transformer3W::magnetizing_connection` now says
which circuit a record states. The PSS/E readers state
`Winding1Terminal`, and the star lowering puts that admittance on winding
1's branch as from side charging `Ym * tap1²`, which bus 1 sees as `Ym`.
Writers whose format has only the other placement keep the value and report
the move with `VALUE_SUBSTITUTED`. PowerIO IR states the field only when it
is not the star point, so 0.11 documents read as they did.

### XIIDM sign conventions

An IIDM battery states `targetP`, `targetQ`, and its reactive limits as
generation; PowerIO storage states power withdrawn, positive when charging.
A converter station's terminal `q` flows from the bus into the station,
while `Hvdc::qf` and `qt` are injected into the bus. The XIIDM and JIIDM
readers and writers now convert both (#700).

### Input collections

`Collection` acquires a ZIP archive or a folder once, inspects it without
parsing electrical values, and parses independent selections: an OpenDSS
master over shared companions, a PyPSA or GridFM dataset root, or a group of
CIM or CGMES documents (#774). ZIP reads are bounded by explicit size,
expansion, count, and ratio limits and verify every member. The CLI
(`powerio collection inspect` and `parse`), Python (`powerio.Collection`), C
(`pio_collection_*`), Julia (`InputCollection`), and the browser converter
use the same selections. The new `powerio-archive` crate holds the bounded
ZIP transport.

### PowerModels and egret JSON carry more

PowerModels and egret keep keys they do not know, so their writers now state,
under PowerIO names those tools leave alone, what their standard fields cannot
hold: area records, case metadata, source identities, rating sets beyond the
three ratings, the detailed connectivity hierarchy, locations and routes,
controls, generator regulation, and HVDC converter detail. Their readers
restore all of it. [Format fidelity](../src/format-fidelity.md) lists the
keys. With the other writer fixes in this candidate, among them the MATPOWER
branch flow columns, the conversion matrix has 25 more lossless cells than
0.11 and no cell is worse.

### Distribution fixes

- OpenDSS transformer and XfmrCode array setters leave the last winding
  selected, as OpenDSS does, so a following scalar property lands on the
  intended winding (#813).
- The OpenDSS and BMOPF fixes of [0.11.10](0.11.10.md): absent line
  ampacity (#762), helper lines that name the same nodes at both ends
  (#765), names OpenDSS cannot carry (#770), and BMOPF provenance (#763).
- The `cim-dist` reader reads CIM16 LV feeders with text enumerations and a
  Diagram Layout.

### Removed

- Python `parse_display`, `DisplayData`, `PwdDisplay`, and `PwdSubstation`,
  and the MCP `display` tool; `parse` reads a `.pwd` display to a `GeoLayer`
  (#612).
- The inert `arrow` Cargo feature of `powerio-capi` (#673).

### Renamed

- `SocwrOpfSolution` names its branch flows `branch_*_flow`, as the other
  solutions do, in Rust, the IR, and the C ABI; the reader accepts the 0.11
  keys. Its `bus_order` and `branch_order` return vectors.
- `to_balanced` and `to_balanced_report` are exported at the facade root.

## Toolchain and dependencies

60.1, rusqlite 0.41 (the libsqlite3-sys advisory fix), sha2 0.11, pyo3 0.30,

## Egret temporal fidelity and conversion evidence

Egret now writes native signed AC branch results and electrical time-series
values after source retention is removed, including IR round trips. Labels and
optional interval durations are retained; unsupported variation is refused.
The Python native Egret oracle checks snapshot extraction, and C/Julia expose
typed time metadata. Unit-commitment semantics remain outside the profile.

The PR workflow exports exact-commit JSON evidence from the same graded cells
as its table and a deterministic ranked backlog. The website can consume those
artifacts and the main Docs deployment's copies. Review compares fixture
coverage, findings and grades; no automatic process may suppress losses or
accept a baseline to make the matrix greener.
