# PowerIO 0.11.8 release notes

PowerIO 0.11.8 adds two distribution formats. MG-RAVENS JSON, LANL's CIM
derived microgrid interchange schema, now reads and writes in both its
balanced and multiconductor profiles. The PowerModelsDistribution
MATHEMATICAL model also reads and writes. OpenDSS lines that use the same
LineCode now share one linecode in BMOPF and PMD output, which more than
halves the size of large feeder and city models. Multiconductor OPF
preparation keeps tiny power factors exactly and refuses DELTA connections to
a neutral or earth. PSS/E transformers stated with CZ=2 or CZ=3 read the
impedance their case states, and PowerModels JSON can carry a 50 Hz system
frequency. Python 3.11 is now the minimum. C ABI 7 and PowerIO IR version 2
are unchanged; the IR schema `pio-ir/2/0.11.8/schema.json` adds the two new
format names. PowerIO.jl follows this release with the same tested binary
artifacts.

The [curated changelog](../../CHANGELOG.md#0118) gives each change in full.

## What is new

### MG-RAVENS JSON

`ravens-json` reads and writes MG-RAVENS
([lanl-ansi/MG-RAVENS](https://github.com/lanl-ansi/MG-RAVENS), Apache-2.0)
(#27, #746). The schema has two profiles, and the classes a document uses
pick the reader:

- The **balanced** profile maps to `BalancedNetwork` and follows the upstream
  MATPOWER converter's conventions.
- The **multiconductor** profile maps to `MulticonductorNetwork` and follows
  `opendss2xml`. It covers per phase segments and loads,
  `PerLengthPhaseImpedance` matrices, transformer tanks with their catalog
  end records and tests, `EnergySource`, machines and power electronics,
  shunt banks, and switches.

A document that mixes the two profiles is refused. Both writers use
deterministic mRIDs, and a write, read, write cycle is byte identical. An
element keeps its `IdentifiedObject.mRID` when a feeder converts between
MG-RAVENS and distribution CIM; transformers are the exception, since RAVENS
keys them by the `PowerTransformer` and CIM by the tank. An unbalanced source
is written as one single phase `EnergySource` per conductor, with an
`EMIT.RAVENS_DIST.SOURCE_SPLIT` finding. A segment with a conductor outside
A, B, C and N is dropped with a finding. Mohamed Numair wrote both readers
and writers; this release moves them onto the shared `powerio-tx` and
`powerio-dist` network models.

```
powerio convert case3_balanced.json --to pmd-json -o case3.pmd.json
powerio convert feeder.dss --to ravens-json -o feeder.ravens.json
```

### PMD MATHEMATICAL JSON

`pmd-math-json` reads and writes the model PowerModelsDistribution solves
(#645, proposed by Robert Ferrando; #746). The writer does what PMD's
`transform_data_model` does:

- PMD's transformer loss model.
- Sources as generators behind their Thevenin impedance.
- `calc_voltage_bases` and `make_per_unit!`.
- Kron reduction of grounded neutrals, on by default and controlled by
  `PmdMathEmitOptions::kron_reduce`.
- The `map` back to the ENGINEERING model.

The reader folds back through that map. It restores a neutral that Kron
reduction removed, both under a wye load and in a wye transformer winding.
Because the MATHEMATICAL model has no winding power rating, the reader states
winding impedances on the emergency rating and reports that it did. The tests
compare the writer field by field with PMD v0.16 exports of five PMD cases.
The ENGINEERING reader points a MATHEMATICAL document at the new token.

Both formats are also available in the browser converter, which now offers
seven distribution outputs (#794), and in the conversion matrix.

### Shared OpenDSS linecodes

The OpenDSS reader used to give every `Line` its own linecode,
`_pio_line_<line>`, so a city model with 40 LineCodes and 50,353 lines wrote
54,399 linecodes, nearly all of them copies of each other. Now lines that
fetched the same LineCode and left it unchanged share one per meter linecode,
named after the LineCode (for example `lc3`). A later edit of the LineCode,
or a unitless LineCode used under another length unit, takes the next free
`_N` suffix. On that city model the BMOPF JSON falls from 171 MB to 73 MB and
the PMD JSON from 171 MB to 83 MB; the IEEE 34 and 123 bus examples drop from
33 and 127 linecodes to 6 and 21 (#785).

Electrical values are unchanged beyond round-off: each line's code times its
length agrees with its old linecode to 6e-16 relative, and OpenDSS solves the
written models to the same node voltages within 1.2e-8 V. A line keeps its own
`_pio_line_` code when sharing could change it: line-level impedance,
frequency or earth return settings, `like=` copies, `switch=yes`, geometry or
spacing, no declared length unit, and base-frequency or earth resistivity
edits after an earlier solve, which keep the impedance OpenDSS cached (#787).

### Multiconductor OPF preparation

- Fixed power factor control gains bounded coefficients,
  `McOpfCoil.power_factor_coefficients = [a, b]`, for the row `a*P + b*Q = 0`
  with `a = sqrt((1 - |pf|)(1 + |pf|))` and `b = pf`. Signed, unity,
  near-unity, tiny, and subnormal power factors keep their value; the old
  `tan(acos(abs(pf)))` slope rounded a power factor of `1e-18` to about
  `6e-17`. The legacy `reactive_slope` stays, and is `None` when the ratio is
  not finite. Build the constraint from the coefficients (#743).
- DELTA loads, generators, capacitors, and transformer windings, and THREE_LEG
  inverters, whose terminal map includes a neutral or earth are refused with
  `BUILD.MULTI.OPF_INVALID`, which names the device and the offending bus
  terminal. Before, a DELTA load on `[a, b, n]` built a model a solver could
  converge on, though it did not describe a valid connection. Explicit BMOPF
  terminal conventions and valid phase-to-phase coil order are unchanged
  (#742).

### Other changes

- PowerModels JSON reads and writes an optional `base_frequency` in Hz. This
  is a PowerIO extension to the format, so a 50 Hz network keeps its
  frequency, including in fresh PSS/E RAW output. Without it the default stays
  60 Hz (#783).
- `powerio_core::cim` collects what the CIM derived formats share:
  deterministic UUIDv5 mRIDs, phase letter and terminal conversions,
  `PhaseCode` expansion, and MG-RAVENS profile detection.
- `GeoLayer::to_geojson` writes straight from the typed features, three to
  five times faster on a city-scale distribution layer, with the same text
  (#784).
- PSS/E RAWX keeps apostrophes in `caseid.title1` and normalizes only embedded
  line terminators (#745).
- The network documentation states that `BusType::Ref` follows each source
  format's reference or slack convention: an angle reference and an active
  power balancing source are not the same thing in every format (#712).

## Behavior changes

- **Python 3.11 is the minimum.** Python 3.9 and 3.10 are past end of life.
  Wheels are `cp311-abi3`, so `pip` on an older Python keeps resolving
  0.11.7. The `bench`, `pandas`, and `mcp` extras drop their Python version
  markers (#786).
- **PSS/E CZ=2 and CZ=3 transformer impedances.** A two-winding transformer
  whose impedance is stated on its winding base (CZ=2) or as load loss and
  impedance magnitude (CZ=3) is now rescaled by `(NOMV1 / bus base kV)²`
  before it is referred to the bus. When NOMV1 differs from the bus base kV,
  the impedance PowerIO reads changes to the value the case states, in RAW
  and RAWX alike. CZ=1, a zero NOMV1, and three-winding transformers are
  unchanged (#772, #782).
- **Malformed pandapower and PowerModels input is refused.** A pandapower
  split-table row whose cell count does not match its columns used to fill
  the missing electrical values with defaults (#766). A PowerModels bus ID
  that is missing or out of range, on a bus or in an equipment reference,
  used to be cast to a default (#767). Both are errors now.
- **Linecode names in distribution output.** BMOPF and PMD documents written
  from OpenDSS reference shared linecodes named after their LineCodes, as
  described above, so the `linecode` table and each line's `linecode`
  reference change. A DSS write and reread now keeps those names; before,
  `_pio_line_x` became `_pio_line_x_1`. Code that looked up a line's
  linecode by the `_pio_line_<line>` pattern should follow the line's
  `linecode` reference instead.
- **PMD time-series profiles in BMOPF output.** PMD's `replace` defaults to
  true, so a bare `values`/`time` PMD profile replaces a load's power instead
  of multiplying it. BMOPF profiles multiply. In BMOPF 0.2.0 output, a PMD
  load shape that states `replace: false` and no offset becomes an active
  BMOPF profile, with its time axis converted from hours to seconds. Every
  other PMD profile, and every profile in BMOPF 0.1.0 output, stays verbatim
  under `extras.time_series` with an `EMIT.BMOPF.RETAINED_SOURCE_ONLY`
  diagnostic. Before, PMD profiles read as BMOPF multiplicative profiles
  (#744, #771).
- **PMD ENGINEERING output.**
  - A ZIP load is written as PMD spells it: `ZIP`, with `zipv` only when the
    coefficients are known. Both `ZIP` and `ZIPV` read.
  - A load with different ZIP coefficients per phase is written as one load
    per phase.
  - An ideal switch stays at zero impedance.
  - A switch keeps its linecode's rating and impedance fields.
  - An empty `name` reads as a network without a name.
- **OpenDSS output for a network with an empty name** writes
  `New Circuit.converted`, as a nameless network does, instead of
  `New Circuit.`.
- **`.json` detection.** A document with PMD's `data_model` marker goes to the
  PMD readers even when its tables look like PowerModels' tables.
- **Invalid DELTA connections are refused** during multiconductor OPF
  preparation (#742).

## Compatibility

- **C ABI 7 is unchanged.**
- **PowerIO IR stays at version 2.** The schema
  `pio-ir/2/0.11.8/schema.json` adds `ravens-json` and `pmd-math-json` to the
  source format names a document can record; the 0.11.7 schema file is
  unchanged. Documents now record producer version 0.11.8.
- **The Rust API changes are additive:** `McOpfCoil.power_factor_coefficients`,
  the `powerio_core::cim` module, the MG-RAVENS modules
  (`powerio_tnd::formats::ravens`, `powerio_dist::ravens`), the PMD
  MATHEMATICAL reader and writer with `PmdMathEmitOptions`, and new variants of
  the nonexhaustive format enums.

## Upgrading

- **Python:** `pip install -U powerio`, on Python 3.11 or newer.
- **Julia:** PowerIO.jl publishes its 0.11.8 release on its own once this
  release is out; update with `Pkg.update("PowerIO")`.
- **Rust:** raise PowerIO requirements to 0.11.8. Multiconductor OPF
  assemblers should build fixed power factor rows from
  `power_factor_coefficients`.

## Known issues

These are present in 0.11.7 as well. The first three are planned for 0.11.9.

- **OpenDSS written from a CIM or MG-RAVENS feeder fails PMD's Kron
  reduction** (#765). When the OpenDSS writer cannot state a network's source
  as a native `Vsource`, as with a distribution CIM or MG-RAVENS feeder, it
  writes one single phase source per conductor, each joined to the bus by a
  helper line. For phases B and C the helper line's two ends name different
  nodes, so OpenDSS reads the file but PMD's `transform_data_model` refuses
  it. The source's internal impedance from a CIM document is also left out,
  with an `EMIT.DSS.EXTRAS_DROPPED` warning.
- **BMOPF provenance keys** (#763). A BMOPF document whose free-form
  `meta.provenance` contains a key such as `length` gets a spurious
  `READ.BMOPF.FIELD_NOT_A_NUMBER` finding. The parsed module then fails to
  serialize to PowerIO IR.
- **Names OpenDSS cannot carry** (#770). A name with spaces or other
  characters OpenDSS splits on, common in CIM `IdentifiedObject.name`, is
  written into OpenDSS verbatim with an `EMIT.DSS.VALUE_SUBSTITUTED` warning,
  and the file does not read back. A bus ID such as `Node 1` makes the
  conversion fail.
- **Unrated OpenDSS lines get a 600 A limit** (#762). An OpenDSS `Line` that
  states no `emergamps` takes OpenDSS's built-in 600 A, which PowerIO records
  as the line's current limit (`i_max` in BMOPF, `cm_ub` in PMD), as PMD's own
  OpenDSS parser does. An OPF that enforces these limits treats 600 A as a
  real rating. A round trip through OpenDSS can also add the limit to
  generated source branches that had none. Whether an unstated rating should
  become a limit is under review in #790.

## Release validation

Source CI, native Python wheels and smoke tests, and paired Julia source tests
run before the release tag. The tag workflow then runs PowerIO.jl against all
five packaged C library archives before it creates a draft. Publication and
the protected registry approvals are separate steps; passing source checks
alone does not mean a package has been published.
