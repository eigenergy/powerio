# PowerIO 0.11.10 release notes

PowerIO 0.11.10 carries compatible conversion and binding fixes from the
0.12 candidate, alongside the OpenDSS/BMOPF fixes and a dependency advisory
remediation. OpenDSS written from a distribution CIM or MG-RAVENS
feeder now reduces in PowerModelsDistribution, a line that states no
ampacity no longer carries OpenDSS's 600 A default into BMOPF or PMD output,
and names OpenDSS cannot carry are replaced and reported instead of written
verbatim. BMOPF reading no longer checks the free-form `meta.provenance`
ledger as schema fields. `rusqlite` 0.41 replaces the bundled SQLite that
RUSTSEC-2026-0459 names, and with it the minimum supported Rust version
rises from 1.88 to 1.89. C ABI 7, PowerIO IR version 2 and the IR schema
`pio-ir/2/0.11.8/schema.json` are unchanged. PowerIO.jl follows this release
with the same tested binary artifacts.

The [curated changelog](../../CHANGELOG.md#01110) gives each change in full.

## What is new

### Native pandapower JSON compatibility

Canonical output declares pandapower package profile 3.2.1 and data format
3.1.0, which are separate upstream version numbers. It emits only the modern
split active/reactive ZIP-load columns. Emitting both those fields and their
legacy aggregate names could make native automatic format migration insert
duplicate columns and fail. The reader still accepts legacy inputs. A native
consumer regression uses the default import options, checks ZIP fractions and
load scaling, and runs a flat-start power flow.
For canonical output, use pandapower 3.2.1 or a compatible newer reader;
the legacy input support does not make this output a pandapower 3.1 profile.

### CGMES active limits and terminal voltage bases

The typed loading limits and their branch-rating projection now consistently
prefer an active `value` over an equipment `normalValue`. For a two-winding
transformer, a current limit uses its own terminal's nominal voltage rather
than the first winding's voltage. For example, a 500 A limit on a 20 kV
winding is about 17.32 MVA even when the other winding is 220 kV. Synthetic
regressions cover both CGMES versions, all three supported limit types,
temporary limits, reversed terminal ordering, IR and canonical output.
A different equipment default remains in retained source bytes and produces
`READ.CGMES.FIELD_UNMAPPED`; canonical output does not claim to preserve it.
Canonical output also preserves the imported identifiers and names of ratio
and phase tap changers, including metadata restored from older IR documents.

Two-winding transformers follow CGMES's common parameter base and one primary
shunt L model. The supported circuit keeps all four terminal admittances when
rated winding voltages differ from nominal bus voltages, including a nonunit
secondary ratio tap. The equivalent branch multiplies series impedance by the
secondary ratio squared and divides its shunt by that factor; canonical output
applies the inverse. Circuit regressions cover both winding ratios and phase
shifts. Nonconforming low-voltage or split-record parameter conventions produce
an explicit approximation diagnostic describing the assumed reference base.
Invalid active ratio magnitudes and arithmetic overflow are refused. See the
[ENTSO-E implementation guide, section 14.19](https://eepublicdownloads.entsoe.eu/clean-documents/CIM_documents/Grid_Model_CIM/CGM%20BUILDING%20PROCESS%20IMPLEMENTATION%20GUIDE_v2.0.pdf).

The calculation projection still uses only the angle of a nonlinear or
tabular phase tap. An active nonunit magnitude now produces
`READ.CGMES.VALUE_APPROXIMATED`. Active tap-step r/x/g/b percentage deviations
that the calculation projection does not apply are also diagnosed, including
when the ratio magnitude is one. The full steps stay in detailed connectivity;
unused steps do not create these calculation warnings. Canonical output places
two-winding series and shunt data on end 1. Combining a nonzero secondary shunt
into that primary L shunt remains an explicit projection loss. A sole primary
shunt emits without a false collapse warning; unequal line charging retains its
loss diagnostic.

**CGMES files written by PowerIO 0.11.0 through 0.11.9.** Those releases
wrote a transformer's to-side shunt on end 2, in end 2's own rated voltage
base. 0.11.10 reads an end 2 shunt on end 1's base, as the ENTSO-E guide and
PowSyBl do, and adds it to the from-side shunt. A file those releases wrote
with a nonzero to-side transformer shunt therefore reads back with that shunt
on the from side, and its value changes whenever the two ends' rated voltages
differ. The reader reports `READ.CGMES.VALUE_APPROXIMATED` for it. PowerIO
does not repair these files: the file does not say which base its writer
used, and reinterpreting it would change correct files from other tools.
Regenerate them from the original network, or from a PowerIO IR document
saved before the export. The current writer cannot place a shunt on end 2
either; it adds a to-side shunt to the from-side shunt and reports
`EMIT.CGMES.VALUE_COLLAPSED`.

### OpenDSS helper lines name the same nodes at both ends

A distribution CIM or MG-RAVENS source has a grounded neutral, so the
OpenDSS writer cannot state it as a native `Vsource`. It writes one single
phase source per conductor, each behind an exact R + (−R) helper line, and
states an ideal closed switch through a helper equivalent of its own. The
helper line always started on node 1 of its private bus, so for phases B and
C it ran from node `.1` to node `.2` or `.3`, and the switch equivalent
numbered its internal bus by position in the same way. PowerModelsDistribution's
`transform_data_model` refused such a deck: Kron reduction needs every line
to name the same nodes at both ends. Each private source bus now takes the
node number of the port it joins, and the internal switch bus repeats the
nodes of the ends it joins. The private buses connect only to these helper
elements, so the circuit is electrically unchanged; the visible change is the
node numbers on the `_pio_ideal_*` and `_pio_switch_*` buses in written
OpenDSS (#765, #798).

### Absent OpenDSS line ampacity stays absent

OpenDSS's `Line` constructor defaults `emergamps` to 600 A. The reader
lowered that default into a typed BMOPF `line.i_max` and PMD `cm_ub` even
when no deck stated a rating, so a DSS to BMOPF round trip could add a 600 A
thermal bound the input never had and tighten a downstream OPF. The reader
now tracks where a line's emergency rating comes from, through LineCode
assignment, `MakeLike`, geometry copies and WireData-derived ampacity, and
types `i_max` only from a rating a deck, line code or conductor states. An
unstated default is treated as void, which differs from
PowerModelsDistribution's parser on purpose: an implicit limit a modeler does
not know about can change OPF optimality. The public model and schema are
unchanged, and the IEEE BMOPF examples are regenerated without the default
(#762, #790). A `switch=yes` Line, with or without an unrated LineCode, and
an ideal switch written to canonical OpenDSS and read again keep an unstated
rating unstated: `switch=yes` used to count as a stated emergency rating,
so an unrated switch carried the 600 A default too.

### Names OpenDSS cannot carry are replaced

Names from other formats can be free text, such as a CIM
`IdentifiedObject.name` of `Cable type A`. A bus id holding a character the
dss tokenizer splits on made the writer refuse the conversion, and every
other such name was written verbatim, with a warning, into a deck OpenDSS
could not parse back. The writer now works on a copy of the network: each
character dss cannot carry (whitespace, `,`, `=`, `!`, quotes, brackets, and
a `.` in a bus id) becomes `_` and `//` becomes `__`; a numeric suffix keeps
names unique within a dss class, where lines and switches share `Line`,
shunts and capacitors share `Capacitor`, and a generator and a fixed dispatch
IBR share `Generator`; and every typed reference follows. Each replacement is
reported as `EMIT.DSS.VALUE_SUBSTITUTED`. A network whose names are already
safe is written from the original, and the model keeps its names; only the
deck changes (#770).

### BMOPF provenance is free-form

BMOPFTools writes a conversion ledger under `meta.provenance`, which both
BMOPF schemas define as free-form tool output. The reader decided which
fields must be numbers by key name at any depth outside `extras`, so a ledger
entry named `length` raised `READ.BMOPF.FIELD_NOT_A_NUMBER`. The finding
also stored its BMOPF document pointer as the diagnostic `target`, which
must point into the IR network, so `powerio::serialize` refused any module
carrying one. The check now skips `meta.provenance`, and the finding records
its pointer as the `source_pointer` detail. A provenance ledger raises no
finding, and a module carrying a genuine bad field serializes (#763, #796).

### The libsqlite3-sys advisory and Rust 1.89

`libsqlite3-sys` 0.38.2, which `rusqlite` 0.40 bundled, carries a SQLite that
can return uninitialized page-cache memory when a database file is opened
together with a crafted `-wal` file whose page size differs
(RUSTSEC-2026-0459, CVE-2026-119375). `rusqlite` moves to 0.41, whose
`libsqlite3-sys` 0.39 bundles SQLite 3.54 with the fix. `rusqlite` 0.41
declares Rust 1.89, so the minimum supported Rust version rises from 1.88 to
1.89; Rust 1.89 has been stable since August 2025. `arrow` and `parquet`
move to 60.1, `zip` to 9.5.0, `uuid` to 1.29, `sha2` to 0.11 and `pyo3` to
0.30 alongside, and the PowSybl harness takes `pandas` 3.1.0 (#749, #751,
#752, #753, #754, #760, #793).

## Review follow-ups

Egret shunts retain their service flags in scalar and time-series output.
A foreign extra cannot populate an omitted native PowerModels field with the
wrong units; collisions are reported. Partial or foreign-shaped Egret branch
results and DC cost extensions remain extras rather than refusing an otherwise
readable case. Applying operating-point columns clears inherited branch results,
so new voltages or dispatch cannot be exported beside a stale solved flow.

Time-series emission applies the scalar loss checks to every point, reports
identical findings once, and builds varying columns incrementally instead of
holding a complete JSON document for every snapshot. Unsupported topology or
non-electrical variation is still refused. In particular, time-varying system
attributes such as `reserve_requirement`, and unsupported element attributes
even on a one-point axis, now produce explicit errors. Earlier readers could
ignore or flatten these inputs; this release intentionally refuses that silent
projection. The supported electrical profile does not implement unit commitment.

Absent CIM distribution frequency remains 60 Hz for all namespace versions;
namespace version does not identify the grid region. Explicit `BaseFrequency`
still wins. XfmrCode winding-count changes reset the active selector consistently
with Transformer. Nested non-finite extension numbers remain visible as a
`NOT_A_NUMBER` finding, and omitted Egret component identities are diagnosed even
when detailed connectivity is retained. Shared JSON extension helpers keep
identity and extra-field precedence consistent between Egret and PowerModels.

## Behavior changes

- Written OpenDSS numbers the nodes of the `_pio_ideal_*` and
  `_pio_switch_*` helper buses after the nodes they join. A deck 0.11.9
  wrote reads as the same circuit; a consumer that matched those node
  numbers textually sees new ones.
- An OpenDSS line or switch with no stated or inherited emergency rating
  lowers to BMOPF and PMD without `i_max` or `cm_ub`. 0.11.9 wrote 600 A.
- A network with names OpenDSS cannot carry writes a deck with replaced
  names and a finding per replacement instead of being refused or written
  verbatim.
- A `READ.BMOPF.FIELD_NOT_A_NUMBER` finding keeps its BMOPF document pointer
  in the `source_pointer` detail instead of `target`.
- Building PowerIO needs Rust 1.89 or newer.

## Compatibility

C ABI 7 and PowerIO IR version 2 are unchanged, and IR documents keep naming
the `pio-ir/2/0.11.8/schema.json` catalog. No public item is renamed or
removed. The minimum supported Rust version is 1.89.

## Release validation

Source CI, native Python wheels and smoke tests, and paired Julia source tests
run before the release tag. The tag workflow then runs PowerIO.jl against all
five packaged C library archives before it creates a draft. Publication and
the protected registry approvals are separate steps; passing source checks
alone does not mean a package has been published.

## Compatible RC backports

PowerModels and Egret retain documented extension fields, including identities,
metadata, areas, rating sets, controls, detailed topology and geography. Native
fields stay authoritative, and a foreign extension-key value remains readable.
These extensions preserve information; they do not imply solver support.
MATPOWER and Egret write complete native signed branch results. Egret electrical
time series preserve labels, durations, dispatch and supported variations through
IR and canonical emission; unsupported intertemporal or topology variation is
refused. The native Egret ModelData oracle checks emitted snapshots.

The existing distribution model also reads CIM16 LV feeders, text enumerations,
wire ampacity and diagram layouts. DSS array setters leave the correct winding
selected, the DSS writer avoids duplicate name-normalization work, and PMD keeps
a stated generator control mode. No electrical model layout changes are needed.

The additive `pio_time_series_time_point` function and Julia `time_points` expose
labels and optional durations without serializing networks. Existing C symbols
and struct layouts remain ABI 7; the IR schema stays version 2. The Julia patch
companion carries overflow rejection, nonconsecutive-axis and DC convention
checks, library probing, preference handling and binding coverage fixes.

The matrix exports exact-commit JSON evidence and a ranked repair backlog from
the same graded cells as the PR table. Coverage reductions and failed checks
remain visible; independent consumer validation is a separate claim. Binding CI
fails if the companion cannot be acquired and records the exact tested pair.

The lockfile resolves compatible dependency updates within the current manifest
constraints while retaining Rust 1.89. Newer incompatible oracle dependency
combinations remain separate until their validation environment supports them.

## Release order and exclusions

Merge the ABI-7-compatible PowerIO.jl patch companion first, then merge this
release with a merge commit and complete its normal release checks. Wait for
Julia 0.11.10 artifact testing and registration before advancing Julia main to
0.12. Merge this updated patch branch into the RC before final RC validation.
Only then advance both repositories and prepare the candidate tag. Tags and
publication still require the maintainer's release request.

The new collection/archive API, additional Sienna/PowerSystems transports,
release-series C/IR versioning, removed compatibility APIs, SOCWR renames and
changed three-winding magnetizing layout remain in 0.12. They are new release
features or incompatible surface changes, not safe 0.11 patch backports. The
1.0 conventions, public numerical-type contract and milestone scope remain open;
see the candidate's readiness checklist.
